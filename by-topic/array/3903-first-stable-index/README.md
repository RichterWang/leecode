# 3903. First Stable Index

**难度**: Easy
**标签**: Array, Prefix Max / Suffix Min（前缀最大值 / 后缀最小值）

---

## 题目描述

给你一个长度为 `n` 的整数数组 `nums` 和一个整数 `k`。

对于每个下标 `i`，定义它的 **不稳定值** 为 `max(nums[0..i-1]) - min(nums[i..n-1])`。

- `max(nums[0..i-1])` 表示从下标 `0` 到 `i-1` 的元素中的 **最大值**
- `min(nums[i..n-1])` 表示从下标 `i` 到 `n-1` 的元素中的 **最小值**

如果某个下标 `i` 的不稳定值 **小于等于** `k`，则称该下标为 **稳定下标**。

返回 **最小** 的稳定下标。如果不存在这样的下标，则返回 `-1`。

---

## 踩坑记录：区间边界到底怎么算

这题最大的坑不在算法，而在**判据的准确边界**。题面写的是 `max(nums[0..i-1])`，看起来前缀不含 `nums[i]`，那么 `i=0` 时前缀是空集、最大值无定义，`i` 的枚举范围就该是 `1..n-1`，**答案不可能是 0**。

但实测下来这个字面读法是错的。实际判据是两侧**都含** `nums[i]`：

```text
max(nums[0..i]) - min(nums[i..n-1]) <= k，i 从 0 起枚举
```

### 分辨用例

关键在于：很多用例在两种读法下答案相同，分辨不出差异。

| 用例 | 字面读法（前缀 `[0..i-1]`，i 从 1 起） | 实际判据（两侧含 i，i 从 0 起） | 预期 |
|---|---|---|---|
| `nums=[5,0,1,4], k=3` | 3 | 3 | 3 |
| `nums=[0,0], k=0` | 1 ✗ | **0** ✓ | 0 |

`[5,0,1,4]` 两种读法都得 3，所以拿它调试**看不出任何问题**。只有 `[0,0]` 这种「答案落在 0」的用例才能把两者区分开——字面读法根本不检查 `i=0`，第一个被检查的 `i=1` 恰好也成立，于是返回了 1。

### 两种判据的完整 trace

`nums = [5,0,1,4], k = 3`，实际判据：

| i | `max(nums[0..i])` | `min(nums[i..3])` | 差 | 判断 |
|---|---|---|---|---|
| 0 | 5 | 0 | 5 | > 3 |
| 1 | 5 | 0 | 5 | > 3 |
| 2 | 5 | 1 | 4 | > 3 |
| 3 | 5 | 4 | 1 | ≤ 3 → **返回 3** |

`nums = [0,0], k = 0`：

| i | `max(nums[0..i])` | `min(nums[i..1])` | 差 | 判断 |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | ≤ 0 → **返回 0** |

### 一个可以自检的性质

既然 `nums[i]` 同属两侧，必然有：

```text
preMax >= nums[i] >= sufMin
```

所以**不稳定值恒为非负**。如果你的实现算出了负的不稳定值，说明区间划分成了不重叠的版本，边界搞错了。这个性质可以当作快速自检。

---

## 解法：前缀最大值 + 后缀最小值

判据只涉及两个量，都可以线性预处理。

### 做法

1. 从右往左递推后缀最小值数组：

```cpp
sufMin[n - 1] = nums[n - 1];
for (int i = n - 2; i >= 0; i--) {
    sufMin[i] = min(nums[i], sufMin[i + 1]);
}
```

`sufMin[i]` 就是 `min(nums[i..n-1])`。

2. 从左往右扫，边走边累积前缀最大值，遇到第一个满足条件的 `i` 立即返回：

```cpp
int preMax = INT_MIN;
for (int i = 0; i < n; i++) {
    preMax = max(preMax, nums[i]);       // 更新在判断之前
    if (preMax - sufMin[i] <= k) return i;
}
return -1;
```

### 关键：更新与判断的顺序

`preMax = max(preMax, nums[i])` 必须写在 `if` **之前**。这样进入判断时 `preMax` 才等于 `max(nums[0..i])`，含 `nums[i]`。

如果写成先判断后更新，`preMax` 只覆盖 `nums[0..i-1]`，就退化成了那个错误的字面读法。**这一行的位置就是正确与错误的分界线。**

后缀那侧则由 `sufMin[i]` 的定义天然保证含 `nums[i]`，不需要额外处理。

## 错误版本：wrong_solution.cpp

保留了照题面字面实现的版本，记录踩坑过程：

```cpp
for(int i = 1; i < n; i++)          // 从 1 起，i=0 从未被检查
{
    back_temp.pop_back();
    temp_max = max(temp_max, nums[i - 1]);   // 前缀只到 i-1
    vector<int> temp = back_temp;
    sort(temp.begin(), temp.end());
    temp_min = temp[0];
    if(temp_max - temp_min <= k) return i;
}
```

用 `back_temp` 存 `nums` 的逆序，`pop_back()` 弹掉的就是 `nums` 的头部，弹 `j` 次后代表后缀 `nums[j..n-1]`。思路本身可行，但有两个问题：

**判据边界错。** 循环从 `i=1` 起、`temp_max` 只累积到 `nums[i-1]`，两处共同实现了字面读法。在 `[0,0] k=0` 上输出 1，预期 0。

修正需要三处联动改动（缺一不可）：

```cpp
for(int i = 0; i < n; i++)              // 1. 从 0 起
{
    temp_max = max(temp_max, nums[i]);  // 2. 前缀含 nums[i]，先更新再判断
    temp_min = *min_element(back_temp.begin(), back_temp.end());
    if(temp_max - temp_min <= k) return i;
    back_temp.pop_back();               // 3. pop 移到末尾，为下一轮弹掉 nums[i]
}
```

不变式：进入第 `i` 轮时已弹 `i` 次，`back_temp` 恰好是 `nums[i..n-1]`。`i=0` 时一次没弹，正是完整数组，符合后缀含 `nums[i]`。`i` 最大 `n-1`，`back_temp` 始终至少剩 1 个元素，取最小值不会越界。

**每轮拷贝 + 全排序。** 只为取一个最小值就做整体排序，复杂度 `O(n² log n)`。换成 `min_element` 可降到 `O(n²)`，预处理成 `sufMin` 数组则是 `O(n)`。

## 调试这类问题的经验

**错误方向能反推 bug 位置。** 如果最小值那侧的区间取宽了（多含了元素），min 会偏小，差值偏大，症状是「本该成立的地方判不成立」，答案偏晚或直接 -1。反之区间取窄，答案会偏早。

**答案落在边界的用例最有价值。** `[0,0] k=0` 这种答案恰好是 0 的用例，专门检验 `i` 的起点；答案恰好是 `n-1` 的用例则检验终点。中间位置的用例往往在多种错误实现下都能通过。

**对拍验证。** 判据一旦确认，写个 `O(n²)` 的双重循环暴力版对拍随机小数据，比手推用例可靠得多。

---

## 复杂度分析

`solution.cpp`（前缀最大 + 后缀最小）：

- **时间复杂度**: `O(n)`，两遍线性扫描
- **空间复杂度**: `O(n)`，`sufMin` 数组

`wrong_solution.cpp`（拷贝 + 排序）：

- **时间复杂度**: `O(n² log n)`
- **空间复杂度**: `O(n)`

> 后缀最小值也可以不开数组：先正向算出前缀最大值数组，再反向扫描时用一个变量维护后缀最小值。但这样只是把 `O(n)` 空间挪到另一边，没有本质改善；除非允许修改 `nums` 或分块处理，`O(1)` 额外空间做不到，因为判据同时需要两个方向的信息。
