# 3904. First Stable Index II

**难度**: Medium
**标签**: Array, Prefix Max / Suffix Min（前缀最大值 / 后缀最小值）

---

## 题目描述

给你一个长度为 `n` 的整数数组 `nums` 和一个整数 `k`。

对于每个下标 `i`，定义它的 **不稳定值** 为 `max(nums[0..i]) - min(nums[i..n-1])`。

- `max(nums[0..i])` 表示从下标 `0` 到 `i` 的元素中的 **最大值**
- `min(nums[i..n-1])` 表示从下标 `i` 到 `n-1` 的元素中的 **最小值**

如果某个下标 `i` 的不稳定值 **小于等于** `k`，则称该下标为 **稳定下标**。

返回 **最小** 的稳定下标。如果不存在这样的下标，则返回 `-1`。

---

## 关键观察：两侧都含 nums[i]

判据里 `nums[i]` **同时属于两个区间**——前缀取到 `i`，后缀从 `i` 开始。这带来两个直接后果。

**`i` 从 0 开始枚举。** 前缀不会是空集，`i = 0` 时前缀就是 `{nums[0]}`，答案完全可能是 0。

**不稳定值恒为非负。** 因为：

```text
max(nums[0..i]) >= nums[i] >= min(nums[i..n-1])
```

这个性质可以当作实现的快速自检——如果算出了负的不稳定值，说明两侧区间被切成了不重叠的版本，边界搞错了。

---

## 解法：前缀最大值 + 后缀最小值

判据只涉及两个量，都能线性预处理，遍历时第一个满足条件的 `i` 即为答案（天然保证最小）。

### 做法

1. 从右往左累积运行最小值，得到后缀最小值序列。
2. 从左往右扫，边走边累积前缀最大值，遇到第一个满足 `preMax - sufMin <= k` 的 `i` 立即返回。
3. 扫完没有命中返回 `-1`。

### 关键：更新与判断的顺序

```cpp
temp_max = max(temp_max, nums[i]);              // 先更新
if (temp_max - suf_min[n - 1 - i] <= k) return i;   // 后判断
```

`temp_max` 的更新必须在 `if` **之前**。这样进入判断时 `temp_max` 才等于 `max(nums[0..i])`，含 `nums[i]`。

如果写成先判断后更新，`temp_max` 只覆盖 `nums[0..i-1]`，判据就变成了 `max(nums[0..i-1]) - min(nums[i..n-1])`——前缀少了一个元素，前缀最大值可能偏小，差值偏小，会误判出更早的答案。**这一行的位置就是正确与错误的分界线。**

### 下标换算

本实现用 `push_back` 构建 `suf_min`，从 `i = n-1` 往左压，所以它是**逆序**存放的：

```text
nums    = [5, 0, 1, 4]
suf_min = [4, 1, 0, 0]      // suf_min[0] 对应原下标 3
          ↑           ↑
     原下标 3      原下标 0
```

对应关系是 `suf_min[j] == min(nums[n-1-j .. n-1])`，所以要取原下标 `i` 的后缀最小值，得写 `suf_min[n - 1 - i]`。

这是最容易写错的地方。直接写 `suf_min[i]` 会拿到原下标 `n-1-i` 位置的后缀最小值——一个完全无关的值。在 `[5,0,1,4] k=3` 上会返回 0（正确答案是 3），因为 `suf_min[0] = 4`，`5 - 4 = 1 <= 3` 立刻命中。

**更省心的写法**是开定长数组按原下标存，省掉换算：

```cpp
vector<int> suf_min(n);
suf_min[n - 1] = nums[n - 1];
for (int i = n - 2; i >= 0; i--) {
    suf_min[i] = min(nums[i], suf_min[i + 1]);
}
// 之后直接 suf_min[i]，不需要 n-1-i
```

或者保留 `push_back` 然后 `reverse(suf_min.begin(), suf_min.end())` 翻回正序。三种写法等价，本文件保留了逆序 + 换算的版本。

### pop_back 是多余的

代码里第二个循环末尾有 `suf_min.pop_back()`。因为 `i` 递增而访问的是 `n-1-i`（从尾部往头部走），弹掉的尾部元素恰好是刚访问过的，所以不影响正确性。但它没有任何作用——既不省内存（`vector` 不会因 `pop_back` 释放容量），也不参与逻辑。

留着的唯一风险是误导读者以为访问依赖弹出。用定长数组的写法就不会有这个疑问。

## Trace

`nums = [5, 0, 1, 4], k = 3`，后缀最小值按原下标为 `[0, 0, 1, 4]`：

| i | `max(nums[0..i])` | `min(nums[i..3])` | 差 | 判断 |
|---|---|---|---|---|
| 0 | 5 | 0 | 5 | > 3 |
| 1 | 5 | 0 | 5 | > 3 |
| 2 | 5 | 1 | 4 | > 3 |
| 3 | 5 | 4 | 1 | ≤ 3 → **返回 3** |

`nums = [0, 0], k = 0`：

| i | `max(nums[0..i])` | `min(nums[i..1])` | 差 | 判断 |
|---|---|---|---|---|
| 0 | 0 | 0 | 0 | ≤ 0 → **返回 0** |

`nums = [5, 4, 3, 2, 1], k = 0`：严格递减，每个 `i` 的前缀最大值都是 5，后缀最小值都是 1，差恒为 4 > 0，全部不满足 → **返回 -1**。

## 常见错误

**变量遮蔽。** 循环体内重新声明同名变量，会让外层变量永远不被更新：

```cpp
int temp = INT_MAX;
for (int i = n - 1; i >= 0; i--) {
    int temp = min(temp, nums[i]);   // 新变量，且读了自己的未初始化值（UB）
}
```

内层的 `int temp` 遮蔽外层，并且用自己未初始化的值参与运算——读未初始化变量是未定义行为。去掉 `int` 才是赋值给外层。编译时加 `-Wshadow` 能直接报出来。

**压入原值而非运行最小值。** `suf_min.push_back(nums[i])` 只会得到 `nums` 的逆序副本，和后缀最小值无关。必须压累积后的 `temp`。

**下标方向搞反。** 逆序存放却按 `suf_min[i]` 访问，见上文「下标换算」。

**忘记 return。** 声明了返回值却走到函数末尾是未定义行为，加 `-Wall` 能当场发现。

## 调试经验

**答案落在边界的用例最有价值。** `[0,0] k=0` 这种答案恰好是 0 的用例专门检验 `i` 的起点；`[5,4,3,2,1] k=0` 检验无解分支；`[7] k=0` 检验 `n=1`。中间位置的用例（比如 `[5,0,1,4] k=3` 答案是 3）在多种错误实现下反而可能碰巧通过。

**错误方向能反推 bug 位置。** 如果最小值那侧的区间取宽了（多含元素），min 偏小，差值偏大，症状是「本该成立的地方判不成立」，答案偏晚或直接 -1。反之区间取窄，答案会偏早。

**对拍最可靠。** 判据确认后，写个 `O(n²)` 的双重循环暴力版对拍随机小数据，比手推用例扎实得多：

```cpp
int brute(vector<int> nums, int k) {
    int n = (int)nums.size();
    for (int i = 0; i < n; i++) {
        int mx = INT_MIN, mn = INT_MAX;
        for (int a = 0; a <= i; a++) mx = max(mx, nums[a]);
        for (int b = i; b < n; b++) mn = min(mn, nums[b]);
        if (mx - mn <= k) return i;
    }
    return -1;
}
```

本解法已用 7 个手工用例 + 5 万组随机数据（`n ≤ 9`，值域 `[0,15)`，`k ∈ [0,6)`）对拍，无差异。

## 复杂度分析

- **时间复杂度**: `O(n)`，两遍线性扫描
- **空间复杂度**: `O(n)`，`suf_min` 数组

> 能否降到 `O(1)` 额外空间？不行。判据同时需要「从左累积」和「从右累积」两个方向的信息，单向扫描无法同时持有。除非允许修改 `nums`（把后缀最小值原地写回去），否则至少需要 `O(n)` 存一侧。把 `suf_min` 换成前缀最大值数组 + 反向扫描时用变量维护后缀最小值，只是把空间挪到另一边，量级不变。
