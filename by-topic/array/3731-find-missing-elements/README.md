# 3731. Find Missing Elements

## 题目信息

- **难度**：Easy
- **分类**：Array, Sorting
- **链接**：https://leetcode.com/problems/find-missing-elements/

## 题目描述

给你一个由互不相同整数组成的数组 `nums`。数组原本包含某个整数范围内的所有值，但中间可能缺少一部分元素。题目保证这个范围的最小值和最大值仍然存在于数组中。

返回该范围内所有缺失整数组成的有序数组；如果没有缺失值，返回空数组。

## 解题思路

### 方法一：排序后线性扫描

先把数组排序。排序后，所有缺失值一定出现在相邻元素之间。

定义一个变量 `reference`：

- 它始终表示“当前期望出现的下一个整数”。
- 初始时令 `reference = nums[0]`。

然后从左到右扫描排序后的数组：

- 如果 `reference == nums[i]`，说明当前值没有缺失，直接把 `reference` 推进到下一个值，即 `reference++`
- 如果 `reference != nums[i]`，说明区间 `[reference, nums[i) )` 内的整数都缺失，把这些数加入答案
- 当前元素处理完成后，必须把 `reference` 更新为 `nums[i] + 1`

### 方法二：排序 + 双指针

也可以把同样的思路写成更明确的双指针形式：

- `i`：指向排序后数组中的当前元素
- `expected`：表示当前应该出现的下一个整数

处理规则是：

- 如果 `nums[i] == expected`，说明当前值存在，二者同时向前推进
- 如果 `nums[i] > expected`，说明 `expected` 缺失，把它加入答案，然后只推进 `expected`
- 由于题目保证元素互不相同且已排序，通常不会出现 `nums[i] < expected`；即使保留这个分支，也只是为了代码更稳健

这种写法和方法一本质一致，只是把“扫描数组”和“推进期望值”拆成了两个更清晰的控制变量。

### 这题里容易犯的错误

#### 1. 循环下标越界

如果写成 `i <= n`，会访问 `nums[n]`，导致越界。这里必须使用 `i < n`。

#### 2. `reference` 的语义混乱

`reference` 不能表示“下一个真实元素”，它应该始终表示“当前期望出现的下一个整数”。

因此，在补完缺失区间之后，正确更新是：

```cpp
reference = nums[i] + 1;
```

而不是：

```cpp
reference = nums[i];
```

也不是：

```cpp
reference = nums[i + 1];
```

否则会把已经存在的元素再次误判成缺失值。

#### 3. 空数组保护

虽然题目通常会给有效输入，但从函数健壮性出发，可以先判断 `nums.empty()`，避免直接访问 `nums[0]`。

## 正确性直观解释

排序后，数组中的元素按从小到大排列。

- 若当前元素正好等于 `reference`，说明这个值存在，不缺失
- 若当前元素大于 `reference`，说明中间断了一段，这一整段就是缺失元素

由于数组元素互不相同，并且最小值和最大值都存在，所以只需要扫描排序后的数组一次，就能完整找出所有缺口。

## 复杂度

**时间复杂度**：`O(n log n + k)`  
其中 `n` 是数组长度，`k` 是输出缺失元素的数量。排序需要 `O(n log n)`，补答案的过程总共输出 `k` 个数。

**空间复杂度**：`O(1)`（不计返回结果）
