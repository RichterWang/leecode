# 2916. 子数组不同元素数目的平方和 II

## 题目信息

- **难度**：Hard
- **分类**：Array, Hash Table, Sliding Window
- **链接**：https://leetcode.com/problems/subarrays-distinct-element-sum-of-squares-ii/

## 题目描述

给你一个下标从 0 开始的整数数组 `nums`。

定义 `nums` 一个子数组的**不同计数**值如下：

令 `nums[i..j]` 表示 `nums` 中所有下标在 `i` 到 `j` 范围内的元素构成的子数组（满足 `0 <= i <= j < nums.length`），那么我们称子数组 `nums[i..j]` 中不同值的数目为 `nums[i..j]` 的不同计数。

请你返回 `nums` 中所有子数组的**不同计数**的**平方和**。

由于答案可能会很大，请你将它对 `10^9 + 7` **取余**后返回。

子数组指的是一个数组里面一段**连续非空**的元素序列。

### 示例

**示例 1：**
```
输入：nums = [1,2,1]
输出：15
解释：
有 6 个子数组：
[1]: 1 个不同元素，1² = 1
[2]: 1 个不同元素，1² = 1
[1]: 1 个不同元素，1² = 1
[1,2]: 2 个不同元素，2² = 4
[2,1]: 2 个不同元素，2² = 4
[1,2,1]: 2 个不同元素，2² = 4
总和 = 1 + 1 + 1 + 4 + 4 + 4 = 15
```

**示例 2：**
```
输入：nums = [1,1]
输出：3
解释：
有 3 个子数组：
[1]: 1 个不同元素，1² = 1
[1]: 1 个不同元素，1² = 1
[1,1]: 1 个不同元素，1² = 1
总和 = 1 + 1 + 1 = 3
```

## 解题思路

### 方法一：暴力枚举 + 哈希表优化 O(n²)

#### 思路分析

**核心思想：** 枚举所有子数组，使用哈希表增量式维护不同元素个数。

**关键优化：** 固定左端点 `i`，滑动右端点 `j` 时，不需要每次重新统计，而是**增量更新**不同元素计数。

#### 算法步骤

1. 外层循环：枚举左端点 `i`（从 0 到 n-1）
2. 对于每个 `i`：
   - 初始化哈希表 `freq` 和不同元素计数 `distinct_cnt = 0`
   - 内层循环：枚举右端点 `j`（从 i 到 n-1）
     - 如果 `nums[j]` 是第一次出现，`distinct_cnt++`
     - 更新 `freq[nums[j]]++`
     - 累加贡献：`answer += distinct_cnt²`
3. 返回答案（对 10^9+7 取模）

#### 为什么这样是优化的？

**暴力做法 O(n³)：**
```cpp
for i in [0, n):
    for j in [i, n):
        set<int> distinct
        for k in [i, j]:  // ← 这层循环可以优化掉
            distinct.insert(nums[k])
        answer += distinct.size()²
```

**优化后 O(n²)：**
```cpp
for i in [0, n):
    map<int, int> freq
    distinct_cnt = 0
    for j in [i, n):
        if freq[nums[j]] == 0:
            distinct_cnt++
        freq[nums[j]]++
        answer += distinct_cnt²  // ← 直接使用维护的计数
```

通过**在线维护**不同元素个数，避免了最内层的重复统计。

#### 实现细节

1. **哈希表的使用：**
   - `unordered_map<int, int>` 记录每个元素的出现次数
   - 当 `freq[nums[j]] == 0` 时，说明这是一个新元素

2. **取模操作：**
   - 每次累加后立即取模，防止溢出
   - 使用 `long long` 计算平方，避免中间结果溢出

3. **边界条件：**
   - 空数组：n=0，直接返回 0
   - 单元素：n=1，返回 1

### 复杂度分析

**时间复杂度：** O(n²)
- 外层循环 O(n)
- 内层循环 O(n)
- 哈希表操作平均 O(1)
- 总体 O(n²)

**空间复杂度：** O(n)
- 哈希表最多存储 n 个不同元素

### 方法二：线段树优化（进阶）

对于更大的数据规模，可以使用**线段树**或**树状数组**优化到 O(n log n)，但实现复杂度较高。

核心思想是维护：
- 每个位置作为右端点时，所有左端点的贡献之和
- 利用数据结构快速更新和查询

（这是 Hard 题的标准解法，本 README 主要讨论 O(n²) 解法）


## 线段树解法易错点

1. **平方和更新公式错误：**
   ```cpp
   // ❌ 错误：加法
   new_sum_square += 2 * delta + old_sum;
   
   // ✅ 正确：乘法
   new_sum_square += 2 * delta * old_sum;
   ```

2. **延迟标记下传时机：**
   - 必须在访问子节点**之前**调用 `push_down`
   - 否则会导致信息不一致

3. **区间完全覆盖判断：**
   ```cpp
   if (ql <= l && r <= qr) {  // 查询区间完全覆盖当前区间
       // 直接返回/处理，不再递归
   }
   ```

4. **模运算的位置：**
   - 每次加法/乘法后都要取模
   - 累加延迟标记时也要取模

## O(n²) 解法易错点

1. **忘记取模：**
   - 平方和可能很大，必须对每次累加结果取模
   - 计算平方时使用 `long long` 防止溢出

2. **哈希表判断错误：**
   - 正确写法：`if (freq[nums[j]] == 0) distinct_cnt++`
   - 错误写法：`if (freq.count(nums[j]) == 0)`（访问会创建元素）

3. **计数器更新顺序：**
   - 必须先判断是否为新元素，再更新频次
   - 顺序错误会导致计数不准确

4. **边界情况：**
   - 空数组虽然题目说非空，但健壮性考虑应处理
   - 单元素数组：应返回 1
