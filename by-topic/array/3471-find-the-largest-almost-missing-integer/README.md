# 3471. Find the Largest Almost Missing Integer

## 题目信息

- **难度**：Easy
- **分类**：Array, Hash Table
- **链接**：https://leetcode.com/problems/find-the-largest-almost-missing-integer/

## 题目描述

给定整数数组 `nums` 和整数 `k`。

如果整数 `x` 恰好只出现在 `nums` 中的一个大小为 `k` 的连续子数组中，则称 `x` 为几近缺失（almost missing）整数。

返回所有几近缺失整数中的最大值。如果不存在这样的整数，返回 `-1`。

## 解题思路

枚举所有长度为 `k` 的连续子数组，并统计每个整数出现在多少个窗口中。

对每个窗口使用 `unordered_set`：

- 保证同一个整数在当前窗口内只计数一次
- 即使一个整数在同一个窗口中重复出现，也只认为它出现在这个窗口中一次

`reference[x]` 表示整数 `x` 出现在多少个长度为 `k` 的窗口中。

遍历所有窗口后：

1. 找出 `reference[x] == 1` 的整数
2. 将这些整数放入候选数组 `answer`
3. 如果候选数组为空，返回 `-1`
4. 否则返回候选数组中的最大值

## 示例

```text
nums = [3, 9, 2, 1, 7]
k = 3
```

长度为 `3` 的窗口是：

```text
[3, 9, 2]
[9, 2, 1]
[2, 1, 7]
```

其中 `3` 和 `7` 只出现在一个窗口中，因此最大几近缺失整数是 `7`。

## 复杂度

设数组长度为 `n`，窗口长度为 `k`：

- **时间复杂度**：`O((n - k + 1) * k)`
- **空间复杂度**：`O(k + u)`，其中 `u` 是不同整数的数量
