# 940. 不同的子序列 II

## 题目信息

- **难度**：Hard
- **分类**：String, Dynamic Programming- **链接**：https://leetcode.com/problems/distinct-subsequences-ii/

## 题目描述

给定一个字符串 `s`，计算 `s` 的**不同非空子序列**的个数。因为结果可能很大，返回答案需要对 `10^9 + 7` 取余。

子序列是通过删除原字符串中零个或多个字符（不改变剩余字符相对顺序）得到的新字符串。

**示例**

| 输入 | 输出 | 说明 |
|---|---|---|
| `"abc"` | 7 | `a, b, c, ab, ac, bc, abc` |
| `"aba"` | 6 | `a, b, ab, ba, aa, aba` |
| `"aaa"` | 3 | `a, aa, aaa` |

约束：`1 <= s.length <= 2000`，`s` 只含小写英文字母。

## 与 115 的本质区别

同样叫「子序列」，但数的对象不同：

| | 115 不同的子序列 | 940 不同的子序列 II |
|---|---|---|
| 数什么 | **下标集合**（方案数） | **不同字符串**（去重） |
| `"bbb"` 取两个 `b` | 3 种（`{0,1} {0,2} {1,2}`） | 1 个（`"bb"`） |
| 状态维度 | `dp[i][j]`，位置 × 位置 | `dp[26]`，**结尾字符** |
| 空间 | `O(nm)` | `O(1)` |

数的对象变了，状态定义就必须跟着换，否则去重无处落脚。**115 的二维位置 DP 在这题上无法去重**——它天生把「相同字符串的不同下标组合」当成不同方案。

## 解题思路

### 状态定义

> `dp[k]` = 扫到当前位置为止，以字母 `'a' + k` 结尾的、互不相同的非空子序列个数。

下标由 `ch - 'a'` 直接算出，`O(1)` 访问，不需要哈希表。

### 为什么按「结尾字符」分组

这是全题设计的核心：**重复只可能发生在结尾字符相同的串之间。**

`"ab"` 和 `"ba"` 永不相同（结尾不同）。会重复的是 `"a"` 与 `"a"`（来自不同位置的 `a`）这类。

把「以 `c` 结尾」的串归到同一格 `dp[c]`，重复就全部集中在这一格。每次扫到 `c` 只覆盖 `dp[c]`，其余 25 格不动——**去重被隔离成单格操作**。

### 为什么 26 格之和就是总数

任意一个非空子序列：

- **必然属于某一格**（有唯一结尾字符）→ 不遗漏
- **只属于一格**（结尾字符唯一确定）→ 不重复

这两条构成数学上的**划分**（partition）。对划分求和即得全体大小：

```dp[0] + dp[1] + ... + dp[25] = 当前不同非空子序列的总个数
```

以 `"ab"` 为例，扫完后不同的非空子序列是 `a, b, ab` 共 3 个：

| 格子 | 装的串 | 个数 |
|---|---|---|
| `dp[0]`（`a` 结尾） | `"a"` | 1 |
| `dp[1]`（`b` 结尾） | `"b"`, `"ab"` | 2 || `dp[2..25]` | 无 | 0 |

`1 + 2 = 3` ✓。`"ab"` 只出现在 `dp[1]`，不会同时落进 `dp[0]`。

### 转移方程

扫到字符 `c` 时，要重新算出「以 `c` 结尾的所有不同子序列个数」。

任何以 `c` 结尾的串 = **某个前缀 + `c`**。前缀有两类：

| 前缀类型 | 种数 | 说明 |
|---|---|---|
| 任意已存在的子序列 | `total` | 26 格全部之和 |
| 空串 | `1` | 对应 `c` 单独成串 |

```cpp
long long total = accumulate(dp.begin(), dp.end(), 0LL) % mod_num;
dp[ch - 'a'] = (total + 1) % mod_num;
```

**不重不漏的证明**

- 不重复：若 `X + c == Y + c`，去掉末尾即得 `X == Y`。前缀不同 ⟹ 结果不同。
- 不遗漏：任取一个以 `c` 结尾的串，去掉末尾 `c`，剩下的要么是空串（对应 `+1`），要么是一个已存在的子序列（在 `total` 里）。

所以 `total + 1` 是**精确值**，而非增量。

### `total` 必须是 26 格之和，不能只看 dp[c]

常见错误：`dp[c] = dp[c] + 1`。

用 `"aba"`（答案 6）对比：

| 扫到 | `dp[c] + 1` | `total + 1` |
|---|---|---|
| `'a'` | `dp[a] = 1` | `dp[a] = 1` |
| `'b'` | `dp[b] = 1` | `dp[b] = 2` |
| `'a'` | `dp[a] = 2` | `dp[a] = 4` |
| **答案** | `2 + 1 = 3` ✗ | `4 + 2 = 6` ✓ |

第二步差在：`dp[b] = 1` 只数出 `{"b"}`，漏了 `"ab"`——因为 `"ab"` 的前缀 `"a"` 存在 `dp[a]` 里。

旧的 `dp[c]` **确实被继承了，但是通过 `total`**。它的角色是「前缀材料」，不是「结果的一部分」。

### 去重的全部实现：`=` 而非 `+=`

`total + 1` 算出的是精确总数，旧 `dp[c]` 数出的串已被新结果完整包含（它作为前缀贡献了 `"旧串 + c"`），再累加就是重复。

等价说法：规定每个串一律以「结尾字符的**最后一次出现**」为标准代表。顺序扫描时当前这个 `c` 就是「至今为止的最后一个 `c`」——**覆盖即认定代表**，无需额外记录位置。

用 `"aaa"` 检验（答案 3）：

| 扫到 | `total` | `dp[a] = total + 1` | 若用 `+=` ||---|---|---|---|
| 第 1 个 `a` | 0 | 1 | 1 |
| 第 2 个 `a` | 1 | 2 | 3 |
| 第 3 个 `a` | 2 | 3 ✓ | 7 ✗ |

### 读写顺序不可颠倒

```cpplong long total = accumulate(...);      // 先读（此时 dp[c] 仍是旧值）dp[ch - 'a'] = (total + 1) % mod_num;   // 后写（覆盖）
```

`total` 需要的是**旧** `dp[c]` 作前缀材料。反过来的话新值混进 `total`，等于用「以 `c` 结尾的新串」再当前缀，重复计数。

## 手工模拟 `s = "aba"`

| 扫到 | `total` | 更新 | `dp[a]` | `dp[b]` | 此刻集合 |
|---|---|---|---|---|---|
| 初始 | — | — | 0 | 0 | `{}` |
| `'a'` | 0 | `dp[a] = 1` | 1 | 0 | a 结尾：`{a}` |
| `'b'` | 1 | `dp[b] = 2` | 1 | 2 | a：`{a}`；b：`{b, ab}` |
| `'a'` | 3 | `dp[a] = 4` | 4 | 2 | a：`{a, aa, ba, aba}`；b：`{b, ab}` |

答案 `4 + 2 = 6` ✓

第三步的四种前缀：

| 前缀 | 来自 | 结果 |
|---|---|---|
| 空 | `+1` | `"a"` |
| `"a"` | `dp[a]` 旧值 | `"aa"` |
| `"b"` | `dp[b]` | `"ba"` |
| `"ab"` | `dp[b]` | `"aba"` |

## 取模：不能照搬 115 的 unsigned 回绕

115 那题可以用 `unsigned long long` 依赖自然回绕，是因为**真实答案保证 `< 2^31`**，中间溢出会自动抵消。

本题答案量级可达 `2^n`（`n` 到 2000），远超 `2^64`，**必须显式 `% (1e9+7)`**。本解法只含加法，取模干净，不会出现负数（无需 `+ MOD` 修正）。

### 踩坑记录：`&` 写成 `%`

```cpp
dp[ch - 'a'] = (total + 1) & mod_num;   // ✗ 位与，不是取模
```

`&` 和 `%` 键位相邻，容易手滑。**这个 bug 在小用例上完全看不出来**：

`1000000007` 的二进制低位恰好是 `...000111`，所以

| 值 | `x & 1000000007` | 是否正确 |
|---|---|---|
| 1 ~ 7 | 原值 | ✓ 巧合 |
| **8** | **0** | ✗ |

`"abc"`(7)、`"aba"`(6)、`"aaa"`(3)、`"abab"`(11) 的中间值最大只到 7，全部落在巧合区间内，**全都会通过**。

能抓出它的最小用例是 `"abcd"`（期望 15）：

| 扫到 | `total` | `(total+1) & mod` | 正确值 |
|---|---|---|---|| `'a'` | 0 | 1 | 1 |
| `'b'` | 1 | 2 | 2 || `'c'` | 3 | 4 | 4 |
| `'d'` | 7 | **8 & mod = 0** ✗ | 8 |

结果返回 `1+2+4+0 = 7`，而非 15。

**教训**：取模误写为位与时，小数据可能因模数的二进制形状而侥幸通过。这类 bug 只能靠稍大用例或 code review 抓。

## 复杂度

- **时间复杂度**：`O(26n)`。每个字符都要对 26 格求和。
  维护一个 `sum` 变量可降到 `O(n)`，但涉及模减法（需 `(sum - old + MOD) % MOD`），收益不大。
- **空间复杂度**：`O(26)` = `O(1)`。与串长无关，只与字符集大小有关。

`26` 这个数来自约束「只含小写英文字母」。若改为含大小写或数字，需扩大数组或改用 `unordered_map<char, long long>`。**看到 26 就应条件反射地确认字符集范围。**

## 验证用例

| 输入 | 期望 | 专门检验 |
|---|---|---|
| `"abc"` | 7 | 基本正确性（`2^3 - 1`） || `"aba"` | 6 | `total` 是否算了所有 26 格（只看 `dp[c]` 会得 3） |
| `"aaa"` | 3 | 是否用 `=` 覆盖（`+=` 会得 7） || `"abab"` | 11 | 综合 |
| `"abcd"` | 15 | `%` 是否误写为 `&` |
| `"abcdefghij"` | 1023 | 中间值增大，进一步压取模 |

`"abab"` 的完整推演：

| 扫到 | `total` | 更新 | `dp[a]` | `dp[b]` |
|---|---|---|---|---|| `'a'` | 0 | `dp[a]=1` | 1 | 0 |
| `'b'` | 1 | `dp[b]=2` | 1 | 2 |
| `'a'` | 3 | `dp[a]=4` | 4 | 2 || `'b'` | 6 | `dp[b]=7` | 4 | 7 |

`4 + 7 = 11` ✓（`a, b, aa, ab, ba, bb, aab, aba, abb, bab, abab`）

## 关键要点小结

1. **数「字符串」而非「下标集合」时，状态要按能隔离重复的特征分组**——本题是结尾字符。
2. **`total` 必须是全部 26 格之和**，因为前缀可以以任何字符结尾。
3. **`+1` 是空前缀**，对应当前字符单独成串。4. **`=` 覆盖是去重的全部实现**，等价于「以最后一次出现为代表」。
5. **先读 `total` 再覆盖**，顺序反了就重复计数。
6. 状态该按什么分组，**由「核心困难是什么」决定**。本题困难是去重，故按结尾字符分组。
