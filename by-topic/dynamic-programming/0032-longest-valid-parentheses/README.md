# 32. Longest Valid Parentheses

- **中文名称**：最长有效括号
- **题目链接**：https://leetcode.com/problems/longest-valid-parentheses/
- **核心思路**：一维 DP，`dp[i]` 表示以下标 `i` 结尾的最长有效括号长度，从前往后填表。

## 题目

给定一个只包含 `'('` 和 `')'` 的字符串，找出最长有效（格式正确且连续）括号**子串**的长度。

```text
输入：s = "(()"        输出：2
输入：s = ")()())"     输出：4
输入：s = ""           输出：0
```

注意是**子串**（连续），不是子序列。

## 状态定义

```text
dp[i] = 以下标 i 结尾的最长有效括号子串长度
```

两个立刻能确定的事实：

1. `s[i] == '('` 时 `dp[i] = 0`。左括号自己没有闭合，不可能作为有效串的最后一个字符。
2. 所以只需要在 `s[i] == ')'` 时讨论转移。

答案是 `max(dp[0..n-1])`，不是 `dp[n-1]`，因为最长的那段不一定正好结束在末尾。

## 两种转移

`s[i] == ')'` 时，看它前一个字符是什么。

### 情况一：`s[i-1] == '('`

末尾正好是一对 `"()"`：

```text
... X X ( )
        ↑ ↑
      i-1 i
```

这两个字符直接配对贡献 2，再接上 `i-2` 位置原有的结果：

```cpp
dp[i] = (i >= 2 ? dp[i - 2] : 0) + 2;
```

`i >= 2` 的判断是防止 `dp[-1]` 越界。`i == 1` 时只有 `"()"`，`dp[1] = 2`。

例子 `"()()"`：`dp[1] = 2`，`dp[3] = dp[1] + 2 = 4`。

### 情况二：`s[i-1] == ')'`（也就是 else if 这一支）

末尾是 `"))"`，`s[i]` 没法跟 `s[i-1]` 配对。但 `s[i-1]` 结尾已经有一段长度为 `dp[i-1]` 的有效串，`s[i]` 要配对的话，只能**跨过整段**去找它左边紧邻的那个字符：

```text
... X [ ← dp[i-1] 这段已匹配 → ] )
      ↑                          ↑
  i-dp[i-1]-1                    i
```

所以 `else if` 的两个条件分别是：

```cpp
i - dp[i - 1] > 0                      // ① 跨过去之后还有字符，下标不越界
&& s[i - dp[i - 1] - 1] == '('         // ② 那个字符是左括号，能和 s[i] 配对
```

**条件 ① 为什么是 `> 0`**

要访问的下标是 `i - dp[i-1] - 1`，它 `>= 0` 等价于 `i - dp[i-1] >= 1`，即 `i - dp[i-1] > 0`。如果不加这个判断，`dp[i-1]` 正好等于 `i` 时（前面整段都已匹配，如 `"()("` 之后再来 `')'` 的变体）会读到 `s[-1]`。

**条件 ② 为什么必须检查**

跨过去的那个字符可能是 `')'`。例如 `"())"`：

```text
i = 2, s[2] = ')', s[1] = ')'
dp[1] = 2（"()"）
i - dp[1] - 1 = 2 - 2 - 1 = -1 → 条件 ① 已经挡掉
```

再如 `")))"`：`dp[1] = 0`，`i - dp[1] - 1 = 0`，`s[0] = ')'` 不是左括号，条件 ② 挡掉，`dp[2]` 保持 0。

两个条件都满足才能转移：

```cpp
dp[i] = dp[i - 1]                                             // 中间那段
      + ((i - dp[i - 1]) >= 2 ? dp[i - dp[i - 1] - 2] : 0)    // 新配对左侧原有的结果
      + 2;                                                     // 新配对的这一对
```

三项含义：

| 项 | 含义 |
|---|---|
| `dp[i-1]` | 被包在中间的那段已匹配长度 |
| `dp[i - dp[i-1] - 2]` | 新配对的左括号**再往左**那部分原有的结果，要接上 |
| `2` | 新找到的这一对括号本身 |

`(i - dp[i-1]) >= 2` 同样是越界保护：要访问 `i - dp[i-1] - 2`，它 `>= 0` 等价于 `i - dp[i-1] >= 2`。

### 为什么没有 else

`s[i] == ')'` 但上面两支都不成立时，说明这个右括号找不到配对对象，`dp[i]` 就应该是 0。`vector<int> dp(n, 0)` 已经初始化为 0，不需要显式写 `else dp[i] = 0`。

## 填表示例

`s = "(()())"`：

| i | s[i] | 分支 | 计算 | dp[i] |
|---|------|------|------|-------|
| 0 | `(` | — | — | 0 |
| 1 | `(` | — | — | 0 |
| 2 | `)` | 情况一 | `dp[0] + 2 = 0 + 2` | 2 |
| 3 | `(` | — | — | 0 |
| 4 | `)` | 情况一 | `dp[2] + 2 = 2 + 2` | 4 |
| 5 | `)` | 情况二 | `dp[4] + dp[-?] + 2`<br>`i-dp[4]=1`，不满足 `>=2`，第二项取 0<br>`4 + 0 + 2` | 6 |

答案 6。

第 5 步细看：`dp[4] = 4` 对应 `"()()"`，`i - dp[4] - 1 = 0`，`s[0] = '('` 配对成功，整段变成 `"(()())"`。

`s = ")()())"`：

| i | s[i] | dp[i] | 说明 |
|---|------|-------|------|
| 0 | `)` | 0 | 循环从 i=1 开始，保持初值 |
| 1 | `(` | 0 | 左括号 |
| 2 | `)` | 2 | 情况一，`dp[0]+2` |
| 3 | `(` | 0 | |
| 4 | `)` | 2 | 情况一，`dp[2]+2 = 4`？ |

这里要留意：`i=4` 走情况一，`dp[4] = dp[2] + 2 = 4`。答案 4，正确。

| 5 | `)` | 0 | 情况二：`i-dp[4]-1 = 0`，`s[0] = ')'` 不是左括号，条件 ② 挡掉 |

最终答案 4。

## 为什么 O(n) 还是跑得慢

这是你提的问题，原因不在复杂度，在常数项和测评噪声。

**1. LeetCode 的 ms 排名不可信**

`n <= 3 * 10^4`，用例总量很小，真实计算时间可能不到 1ms。显示的耗时里判题框架启动、用例反序列化、`string` 构造占了大头。同一份代码连续提交几次，百分位能差几十。

**2. `vector<int> dp(n, 0)` 有堆分配 + 零初始化**

这是整个解法里唯一的动态内存操作，在总耗时中占比不低。栈解法的 `stack<int>` 同理，所以两者实测常数差不多。

**3. 访存模式对缓存不友好**

```cpp
dp[i - dp[i - 1] - 2]
```

这是**数据依赖的跳跃访问**，下标由运行时数据决定。编译器无法向量化，CPU 硬件预取器也猜不中，容易 cache miss。顺序扫描的方案在这一点上有明显优势。

**4. 分支密集且难预测**

`if (s[i] == ')')` 嵌套 `if / else if`，括号序列的模式不规则，分支预测失败率高。每次 misprediction 大约 15-20 个周期。

**5. `string s` 按值传参**

多一次完整字符串拷贝。改成 `const string& s` 可以省掉，LeetCode 接受这个签名。

## 常数最优：双向计数法

不开数组、不用栈，只有两个 `int` 计数器，纯顺序扫描，`O(1)` 空间：

```cpp
int longestValidParentheses(const string& s) {
    int n = (int)s.size(), ans = 0;

    for (int i = 0, left = 0, right = 0; i < n; i++) {
        s[i] == '(' ? left++ : right++;
        if (right > left)       left = right = 0;
        else if (left == right) ans = max(ans, 2 * right);
    }

    for (int i = n - 1, left = 0, right = 0; i >= 0; i--) {
        s[i] == '(' ? left++ : right++;
        if (left > right)       left = right = 0;
        else if (left == right) ans = max(ans, 2 * left);
    }

    return ans;
}
```

**为什么必须扫两遍**

正向扫描时，`right > left` 说明右括号多余，当前这段彻底废了，可以安全归零重新开始。

但 `left > right`（左括号多余）**无法判断后面会不会补上**，所以只能继续累加，永远等不到 `left == right` 的结算时刻。`"(()"` 就是这种情况：正向扫完 `left=2, right=1`，一次都没结算。

反向扫一遍，角色互换：这次 `left > right` 成为可以归零的条件，于是 `"(()"` 从右往左读成 `")(("`，走到第二个字符时 `left=1, right=1` 结算出 2。

两遍合起来覆盖所有情况。

**为什么结算条件是 `left == right` 而不是别的**

计数器只在遇到不平衡时归零，所以归零点之后的区间始终满足"前缀的右括号数不超过左括号数"（正向）。在这个前提下，`left == right` 就意味着从归零点到当前位置是一个完整的有效串，长度 `2 * right`。

## 对比

| 方案 | 时间 | 空间 | 常数 | 备注 |
|------|------|------|------|------|
| DP | O(n) | O(n) | 中 | 状态定义清晰，转移需要仔细推 |
| 栈 | O(n) | O(n) | 中 | 栈底存"上一个未匹配右括号的下标" |
| 双向计数 | O(n) | O(1) | 小 | 需要想到扫两遍，最优解 |

三者复杂度同阶，实测差异来自内存分配和访存模式。
