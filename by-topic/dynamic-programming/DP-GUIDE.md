# Dynamic Programming Guide

## 什么时候考虑动态规划

判断一道题是否适合动态规划，不要先问“能不能递归”，而是先问下面三个问题：

1. 能不能把原问题拆成若干个同类子问题。
2. 不同拆法之间会不会出现重复子问题。
3. 原问题的最优解能不能由子问题的最优解组合得到，也就是是否存在最优子结构。

如果这三点都比较明显，这题通常就值得往动态规划方向想。

一个更实用的判断句是：

> DP 不是“能递归就做”，而是“有状态、会重复、能转移”。

## 常见动态规划类型

在正式写状态之前，先判断题目属于哪一类 DP：

- **线性 DP**：状态沿数组或序列下标推进。
- **区间 DP**：状态是一个连续区间 `[l, r]`。
- **背包 DP**：状态和容量、选取数量、价值有关。
- **树形 DP**：状态挂在树节点上。
- **状态压缩 DP**：状态是一个集合或位掩码。
- **博弈 DP**：状态表示当前局面下的最优收益或必胜必败。

例如：

- `LeetCode 1563. Stone Game V`：每次操作后都在更小的连续区间上继续，因此是**区间 DP**。
- `LeetCode 2029. Stone Game IX`：虽然看起来像博弈题，但最终可以压缩成取模计数的分类讨论，不需要 DP。
- `LeetCode 3702. Longest Subsequence With Non-Zero XOR`：虽然是子序列题，但利用 XOR 性质可以直接分类讨论，不需要 DP。

## 动态规划的固定思路

### 1. 定义状态

先明确 `dp` 数组的意义。好的状态定义通常满足两个条件：

- 能完整描述一个子问题。
- 方便由更小状态转移过来。

例如区间 DP 常写成：

```text
dp[l][r]
```

表示在区间 `[l, r]` 上开始处理时，能够得到的最优答案。

### 2. 确定边界条件

问自己：最小规模的子问题是什么？这个子问题的答案能不能直接写出来？

例如在 `Stone Game V` 中：

- 当区间只剩一个元素时，无法继续切分。
- 所以 `dp[i][i] = 0`。

### 3. 找状态转移方程

状态转移的本质，是在当前状态下枚举所有可能的决策。

要问自己：

- 当前状态下能做哪些选择？
- 每个选择会转移到哪个子状态？
- 当前收益和子状态答案怎么合并？

例如在 `Stone Game V` 中：

- 枚举切分点 `k`。
- 计算左右区间和。
- 根据左右和大小，决定下一步进入左区间还是右区间。
- 用“本轮得分 + 子区间最优解”更新 `dp[l][r]`。

### 4. 确定计算顺序

不是所有 DP 都是简单的“从小到大”。要具体到依赖关系。

- 线性 DP：通常按下标从小到大或从大到小。
- 区间 DP：通常按区间长度从小到大。
- 记忆化搜索：顺序由递归自动处理。

在区间 DP 中，`dp[l][r]` 常依赖更短区间，所以要先算短区间，再算长区间。

### 5. 确定最终答案位置

最后明确：题目要的究竟是哪一个状态。

常见情况：

- 整个数组的区间 DP：答案是 `dp[0][n - 1]`
- 线性 DP：答案可能是 `dp[n - 1]` 或 `max(dp[...])`
- 背包 DP：答案可能是 `dp[n][W]`

## 以 Stone Game V 为例

### 状态定义

```text
dp[left][right]
```

表示在区间 `stoneValue[left..right]` 上开始游戏时，Alice 最多可以获得多少分。

### 边界条件

```text
dp[i][i] = 0
```

### 前缀和

为了快速计算区间和，先预处理：

```text
prefix[i + 1] = prefix[i] + stoneValue[i]
```

则区间和：

```text
sum(l, r) = prefix[r + 1] - prefix[l]
```

### 转移

对于区间 `[left, right]`，枚举切分点 `k`：

- 左区间 `[left, k]`
- 右区间 `[k + 1, right]`

如果：

- `leftSum < rightSum`，则转移到左区间
- `leftSum > rightSum`，则转移到右区间
- `leftSum == rightSum`，则取左右两种选择的较优者

### 填表顺序

按区间长度从小到大：

- 先处理长度为 `1`
- 再处理长度为 `2, 3, ..., n`

## 如何判断数组开 `n` 还是 `n + 1`

这不是看题目规模，而是看你的下标语义。

核心判断句：

> 如果你会合法访问到下标 `n`，就开 `n + 1`；如果只会访问到 `0..n-1`，开 `n` 就够了。

### 常见情况

- 原数组、普通下标状态数组：通常开 `n`
- 前缀和数组：通常开 `n + 1`

例如：

```text
prefix[0] = 0
prefix[i] 表示前 i 个元素之和
```

此时当要求整个区间 `[0, n - 1]` 的和时，会访问 `prefix[n]`，所以必须开 `n + 1`。

而区间 DP 中：

```text
dp[l][r]
```

只要 `l` 和 `r` 都在 `0..n-1`，那么 `dp` 开 `n x n` 就够了。

## 常见误区

### 1. 看到递归就直接上 DP

递归只是表达方式，不等于一定要 DP。很多题虽然能递归拆，但如果：

- 没有明显重复子问题
- 有数学规律可直接分类讨论
- 有贪心或双指针可以一次做完

就没必要硬做 DP。

### 2. 状态定义过大或不自然

状态定义太复杂，往往意味着问题还没有想透。

例如某些题可以先压缩信息，只保留真正影响后续转移的维度，而不是把所有过程信息都放进状态。

### 3. 只会写状态，不会检查依赖顺序

写出转移方程之后，还要确认填表顺序能保证依赖项已知。否则即使方程正确，代码也可能算错。

## 一个简洁的 DP 检查清单

做题时可以按下面顺序快速过一遍：

1. 这题有没有重复子问题？
2. 原问题最优解能不能由子问题最优解组成？
3. 这题属于哪一类 DP？
4. `dp` 的状态定义是什么？
5. 边界条件是什么？
6. 当前状态有哪些决策？
7. 状态转移方程怎么写？
8. 按什么顺序计算？
9. 最终答案在哪个状态里？

这套流程适用于大多数基础和中等难度的动态规划题。
