# 115. 不同的子序列

**难度**: Hard
**标签**: String, Dynamic Programming（计数型 DP）
**链接**: https://leetcode.com/problems/distinct-subsequences/

---

## 题目描述

给你两个字符串 `s` 和 `t`，统计并返回在 `s` 的 **子序列** 中 `t` 出现的个数。

约束：`1 <= s.length, t.length <= 1000`，均由小写英文字母组成。题目保证答案在 32 位有符号整数范围内。

---

## 关键前提：数的是「下标集合」，不是「不同字符串」

`s = "bbb"`, `t = "bb"` 的答案是 **3**，不是 1。

三种方案选出的字符串长得一模一样，都是 `"bb"`，但它们来自不同的下标组合：`{0,1}`、`{0,2}`、`{1,2}`。**题目数的是这些下标组合的个数**，所以不去重。

再验证官方例子：`s = "rabbbit"`, `t = "rabbit"` → 3 个 `b` 里挑 2 个，`C(3,2) = 3`。✓

这一点没搞清，后面所有推导都会跑偏。

---

## 为什么贪心不行

判断 `t` 是否为 `s` 的子序列，双指针贪心 `O(n+m)` 就够了：

```cpp
int i = 0;
for (char c : s) if (i < t.size() && t[i] == c) i++;
return i == t.size();
```

但它无法改造成计数。贪心只走**一条**路径——遇到能匹配的立刻吃掉。而计数要求把**所有**路径都算上。在 `"bbb"` 里贪心找到 `{0,1}` 就返回了，另外两种它根本不会走。

## 解法一：位掩码暴力（`brute_force_solution.cpp`）

`s` 的每个字符「选 / 不选」，共 `2^m` 种方案，用 `m` 位二进制数 `mask` 表示：第 `i` 位为 1 就取 `s[i]`。

```cpp
for (int mask = 0; mask < (1 << m); mask++) {
    string temp;
    for (int i = 0; i < m; i++) {
        if (mask & (1 << i)) temp.push_back(s[i]);
    }
    if (temp == t) answer++;
}
```

### 位运算解读

`1 << i` 造出「只有第 `i` 位是 1」的探针（位编号从右往左、从 0 开始）：

| 表达式 | 二进制 | 十进制 |
|---|---|---|
| `1 << 0` | `0001` | 1 |
| `1 << 1` | `0010` | 2 |
| `1 << 2` | `0100` | 4 |
| `1 << 3` | `1000` | 8 |

`mask & (1 << i)` 用探针查询第 `i` 位。除第 `i` 位外其余位都被探针的 0 清零，所以**结果非零 ⟺ `mask` 第 `i` 位是 1**：

```text
mask     = 1 0 1 1
1 << 3   = 1 0 0 0
           ─────────  &
结果      = 1 0 0 0   → 8（非零），第 3 位是 1
```

`mask < (1 << m)` 即 `mask < 2^m`，让 `mask` 取遍 `[0, 2^m)` 共 `2^m` 个值。`m` 个二进制位的组合数是 `2^m`，`s` 的子序列数也是 `2^m`，**两者一一对应**，所以不重不漏、无需去重。

三个数的角色不能混：

| 表达式 | 含义 | 用途 |
|---|---|---|
| `mask` | 当前方案 | 循环变量，全程**只读** |
| `1 << i` | 第 `i` 位探针 | 工具，用完即弃 |
| `1 << m` | 方案总数 `2^m` | 循环上界，固定不变 |

### `s = "abc"` 完整对照

| mask | 二进制 | 生成 |
|---|---|---|
| 0 | `000` | `""` |
| 1 | `001` | `"a"` |
| 2 | `010` | `"b"` |
| 3 | `011` | `"ab"` |
| 4 | `100` | `"c"` |
| 5 | `101` | `"ac"` |
| 6 | `110` | `"bc"` |
| 7 | `111` | `"abc"` |

内层 `i` **必须递增**。`i` 递增 push 保证字符按原下标顺序排列，生成的才是子序列；写成 `for (int i = m-1; i >= 0; i--)` 得到的是逆序串，全错。

### 复杂度与致命局限

时间 `O(2^m · m)`，空间 `O(m)`。

**这个版本过不了本题**，实测报错：

```text
runtime error: shift exponent 33 is too large for 32-bit type 'int'
输入: s = "bccbcdcabadabddbccaddcbabbaaacdba" (长度 33)
```

`1` 是 `int` 字面量，32 位。C++ 规定移位位数 `>=` 类型位宽是**未定义行为**，`1 << 33` 直接触发 UBSan。

改成 `1LL << m` 能消掉 UB，但**跑不完**：`m = 33` 是 86 亿次循环，`m = 1000` 时 `2^1000` 比宇宙原子总数还多。**指数复杂度无法用常数优化拯救。**

这个报错不是 bug，而是算法选择的硬性淘汰信号。

> **通用习惯**：看到 `1 << m` 先确认 `m` 的上界。`m <= 20`（`2^20 ≈ 100 万`）才是暴力可行区间；`m` 能到 30 以上就说明这题不是位掩码题。

代码里加了 `if (m > 20) return -1;` 守卫，保留它作为**对拍基准**——小数据上验证正解的正确性。

## 解法二：递归 + 双指针

暴力法的根本缺陷是「先全部决策完再验证」。换成「边决策边匹配」就能剪枝，也能复用状态。

`i` 指向 `s`，`j` 指向 `t`，`dfs(i, j)` 返回「用 `s[i..]` 匹配 `t[j..]` 的方案数」。

```cpp
long long dfs(const string& s, const string& t, int i, int j) {
    if (j == t.size()) return 1;   // t 配完了，这是一条完整方案
    if (i == s.size()) return 0;   // s 用光但 t 没配完，此路不通

    long long res = dfs(s, t, i + 1, j);              // 不用 s[i]
    if (s[i] == t[j]) {
        res += dfs(s, t, i + 1, j + 1);               // 用 s[i] 匹配 t[j]
    }
    return res;
}
```

### 核心：`s[i] == t[j]` 时有两个选择

这是整道题的引擎。字符相等时，你**不是必须**用它：

1. **用** `s[i]` 匹配 `t[j]` —— 两个指针都前进
2. **不用** 它，留着让后面的字符来匹配 `t[j]` —— 只有 `i` 前进

两条路径都合法，都要计入总数，所以**相加**。

回到 `"bbb"` / `"bb"`：`s[0]='b'` 匹配 `t[0]='b'` 时，用它（后面从 `s[1]` 找第二个 b，2 种）+ 不用它（后面从 `s[1]` 重新找两个 b，1 种）= 3。✓

### 出口顺序不能反

必须**先判 `j == t.size()`**。因为 `i` 和 `j` 可能同时到头，这时是成功匹配该返回 1；先判 `i` 会误返回 0。

那个 `return 1` 是整个计数的**种子**——所有方案数都是从它累加上来的。

| 条件 | 返回 | 含义 |
|---|---|---|
| `j == m` | **1** | 成功路径，计 1 种方案 |
| `i == n && j < m` | 0 | 失败路径，贡献 0 |
| 否则 | 分支求和 | 两种选择相加 |

### 递归展开：`s = "bbb"`, `t = "bb"`

```text
dfs(0,0)  s[0]='b'==t[0]  → dfs(1,0) + dfs(1,1)
  dfs(1,0)  'b'=='b'      → dfs(2,0) + dfs(2,1)
    dfs(2,0)  'b'=='b'    → dfs(3,0) + dfs(3,1)
      dfs(3,0) → i 到头, j=0<2 → 0
      dfs(3,1) → i 到头, j=1<2 → 0
      = 0
    dfs(2,1)  'b'=='b'    → dfs(3,1) + dfs(3,2)
      dfs(3,1) → 0
      dfs(3,2) → j 到头   → 1
      = 1
    dfs(1,0) = 0 + 1 = 1
  dfs(1,1)  'b'=='b'      → dfs(2,1) + dfs(2,2)
    dfs(2,1) = 1          ← 重复计算！
    dfs(2,2) → j 到头     → 1
    = 2
  dfs(0,0) = 1 + 2 = 3   ✓
```

`dfs(2,1)` 被算了两次，且两次返回值**必然相同**——函数结果**只由 `(i, j)` 决定**，与「怎么走到这里」无关。

**重叠子问题 + 无后效性**，DP 的两个前提都齐了。

## 解法三：记忆化搜索

加个 `memo` 缓存，`O(2^m)` 直接降到 `O(n·m)`：

```cpp
long long dfs(int i, int j) {
    if (j == m) return 1;
    if (i == n) return 0;
    if (memo[i][j] != -1) return memo[i][j];

    long long res = dfs(i + 1, j);
    if (s[i] == t[j]) res += dfs(i + 1, j + 1);
    return memo[i][j] = res;
}
```

状态数 `n × m`，每个只算一次。上面那个 33 长度的用例只有 `33 × 7 = 231` 个状态，瞬间出结果。

**这一版已经能 AC。**

## 解法四：递推 DP

记忆化是自顶向下（从 `(0,0)` 往下问剩余部分），递推是自底向上（从边界往回填）。两者等价，后者省掉递归栈开销。

### 状态定义

**`dp[i][j]` = `s` 的前 `i` 个字符中，能凑出 `t` 的前 `j` 个字符的方案数。**

用「前 `i` 个」而非「以 `i` 结尾」，边界好写很多，`dp` 开 `(n+1) × (m+1)`，答案是 `dp[n][m]`。

注意「前 `i` 个字符」的最后一个下标是 `i-1`，别写错。

### 转移方程

```cpp
dp[i][j] = dp[i - 1][j];                              // 不用 s[i-1]
if (s[i - 1] == t[j - 1]) {
    dp[i][j] += dp[i - 1][j - 1];                     // 用 s[i-1] 匹配 t[j-1]
}
```

和递归的两个分支一一对应，只是方向相反（一个累积前缀，一个处理剩余后缀）。

### 初始化：本题第一大坑

**`dp[i][0] = 1`，不是 0。**

「用 `s` 的前 `i` 个字符凑出空串」有一种方案——什么都不选。包括 `dp[0][0] = 1`。

这个 `1` 是整张表的**种子**，对应递归里的 `if (j == m) return 1`。**写成 0 的话整张表全是 0，返回 0。**

`dp[0][j]`（`j > 0`）= 0：空的 `s` 凑不出非空的 `t`。

### 手推验算：`s = "bbb"`, `t = "bb"`

`j = 0` 一列全为 1（种子）；`s` 的每个字符都是 `'b'`，与 `t` 的每个字符都相等，所以每格都走「相加」分支。

| | j=0 (`""`) | j=1 (`"b"`) | j=2 (`"bb"`) |
|---|---|---|---|
| **i=0** (`""`) | 1 | 0 | 0 |
| **i=1** (`"b"`) | 1 | 0+1=**1** | 0+0=**0** |
| **i=2** (`"bb"`) | 1 | 1+1=**2** | 0+1=**1** |
| **i=3** (`"bbb"`) | 1 | 2+1=**3** | 1+2=**3** |

`dp[3][2] = 3` ✓

顺带验证 `dp[3][1] = 3`：从 `"bbb"` 里选一个 `b`，确实有 3 种。

---

## 推送（push）视角：本仓库 `solution.cpp` 的写法

上面的转移是**拉取**（pull）——站在 `dp[i][j]` 问「从哪来」。也可以反过来**推送**（push）——站在已算好的 `dp[i][j]` 问「能贡献给谁」。

此时要处理的是下一个字符 `s[i]`，目标是 `t[j]`（**注意不带 `-1`**，因为 `i` 是「已处理完的个数」，下一个待处理的正好是 `s[i]`）：

```cpp
dp[i + 1][j] += dp[i][j];                        // 不用 s[i]，方案原样延续
if (j < m && s[i] == t[j]) {
    dp[i + 1][j + 1] += dp[i][j];                // 用 s[i] 顶 t[j]
}
```

### 两者等价

把推送版换元（令 `i' = i+1`, `j' = j+1`）：

| 推送 | 换元后 | 拉取 |
|---|---|---|
| `dp[i+1][j] += dp[i][j]` | `dp[i'][j] += dp[i'-1][j]` | `dp[i][j] = dp[i-1][j]` ✓ |
| `dp[i+1][j+1] += dp[i][j]` | `dp[i'][j'] += dp[i'-1][j'-1]` | `dp[i][j] += dp[i-1][j-1]` ✓ |
| `s[i] == t[j]` | `s[i'-1] == t[j'-1]` | `s[i-1] == t[j-1]` ✓ |

同一个转移，只是站在起点还是终点看。

### 实际差别

| | 拉取 | 推送 |
|---|---|---|
| 赋值 | `=` 然后 `+=` | 全部 `+=` |
| 初始化 | `dp[i][0]` 整列手填 1 | 只填 `dp[0][0] = 1` |
| 遍历 | `i: 1..n`, `j: 1..m` | `i: 0..n-1`, **`j: 0..m`** |
| 越界风险 | `i-1`, `j-1` 下界 | `i+1`, `j+1` 上界 |

推送版更省心的地方：`dp[i][0] = 1` 那一整列会沿「不用」分支**自动推出来**，不必手填。

### 推送版的专属坑：内层 `j` 必须到 `m`

```cpp
for (int j = 0; j <= m; j++)      // 不是 j < m
```

`dp[i][m]` 表示「`t` 已经配完」的方案。这些方案还需要沿「不用 `s[i]`」传递到 `dp[i+1][m]`——`s` 剩下的字符全部跳过也是合法的。

漏了会丢失所有**中途就配完 `t`** 的方案。最小反例 `s = "ab"`, `t = "a"`（答案 1）：

- `i=0`：`dp[1][0] += 1`；`s[0]=='a'==t[0]` → `dp[1][1] += 1`
- `i=1`：`j` 只到 0，`dp[1][1]` 的 1 **永远卡在第 1 行传不出去**
- 返回 `dp[2][1] = 0` ✗

也正因为 `j` 能取到 `m`，`if` 里必须有 `j < m` 守卫——`j == m` 时不能再往 `t[m]` 匹配（越界），只走「不用」这一支。

### 推送版手推：`s = "bbb"`, `t = "bb"`

**i=0**（处理 `s[0]='b'`），`dp[0][0]=1`：
- `dp[1][0] += 1` → 1；匹配 `t[0]` → `dp[1][1] += 1` → 1

**i=1**（处理 `s[1]='b'`）：
- 从 `dp[1][0]=1`：`dp[2][0]` → 1；`dp[2][1] += 1` → 1
- 从 `dp[1][1]=1`：`dp[2][1] += 1` → **2**；`dp[2][2] += 1` → 1

**i=2**（处理 `s[2]='b'`）：
- 从 `dp[2][0]=1`：`dp[3][0]` → 1；`dp[3][1] += 1` → 1
- 从 `dp[2][1]=2`：`dp[3][1] += 2` → **3**；`dp[3][2] += 2` → 2
- 从 `dp[2][2]=1`：`dp[3][2] += 1` → **3**；`j == m`，不再匹配

| | j=0 | j=1 | j=2 |
|---|---|---|---|
| i=0 | 1 | 0 | 0 |
| i=1 | 1 | 1 | 0 |
| i=2 | 1 | 2 | 1 |
| i=3 | 1 | 3 | **3** |

和拉取版填出的表**完全一致**。注意 `dp[3][2]` 收到了两笔贡献（2 和 1）——这就是必须用 `+=` 而非 `=` 的原因。

## 溢出：本题最深的坑

### 现象

用 `long long` 也会被 UBSan 报有符号溢出。**这不是 bug。**

题目保证的是「**答案**在 32 位有符号整数范围内」——只约束 `dp[n][m]`，**对中间格子没有任何保证**。

### 反例

```text
s = "aaa...a" (100 个 a) + "z"
t = "aaa...a" (50 个 a)  + "b"
```

**答案是 0**——`s` 里根本没有 `b`，`t` 永远配不完。

但填表时 `dp[100][50]` = 从 100 个 `a` 里选 50 个 = `C(100,50) ≈ 1.0 × 10^29`。

| 类型 | 上限 |
|---|---|
| `long long` | `9.2 × 10^18` |
| `unsigned long long` | `1.8 × 10^19` |
| `__int128` | `1.7 × 10^38` |
| 需装下的 `C(100,50)` | `1.0 × 10^29` |
| `C(1000,500)` | `~10^299` |

`s` 长度可到 1000，**没有任何定宽整数类型够用**。换更大的类型这条路走不通。

### 为什么中间会溢出而答案不会

`dp[n][m]` **不是所有 `dp[i][j]` 的总和**。把它拆开看：

```text
dp[n][m] = Σ  dp[i][j] × （从 (i,j) 走到 (n,m) 的走法数）
```

后面那个因子是**系数**。上例中 `dp[100][50] = 10^29`，但它的系数是 **0**——那 `10^29` 种方案全都停在「已配好 50 个 a，还差一个 b」，而 `s` 剩下的只有 `z`，全是死路。

**巨大 × 0 = 0。** 中间值再大，走不到终点就不影响答案。

像走迷宫数路径：某个中间房间可以有天文数字条路通到它，但如果它所有出口都是死胡同，它对「入口到出口的路径数」贡献为 0。

**所以「答案有界」推不出「中间值有界」**，两者之间没有大小关系。

### 解法：unsigned long long 让它自然回绕

```cpp
vector<vector<unsigned long long>> dp(n + 1, vector<unsigned long long>(m + 1, 0));
```

只改类型，逻辑一字不动。

**注意：unsigned 起作用不是因为范围变大**（只多一倍，杯水车薪），而是因为溢出行为的性质变了：

| | 有符号溢出 | 无符号溢出 |
|---|---|---|
| C++ 标准 | **未定义行为（UB）** | **定义为对 `2^64` 取模** |
| 后果 | 编译器可任意优化，UBSan 报错 | 保证回绕，结果可预测 |

溢出从「事故」变成了「运算规则」——你不再是在算普通整数，而是在**模 `2^64` 的算术系统**里做加法。

### 为什么模运算仍得到精确答案

三个条件同时成立：

**1. 整个 DP 只有加法。** 而加法与取模**同态**：

```text
(a + b) mod M = ((a mod M) + (b mod M)) mod M
```

「先算完再取模」与「每步都取模」结果相同。所以即使中途每格都回绕，`dp[n][m]` 装的值**严格等于「真实答案 mod 2^64」**——不是近似，是精确相等。

**2. 真实答案 `A < 2^31 < 2^64`。** 题目保证。

**3. 小于模数的数取模等于自身。** `A mod 2^64 = A`。

串起来：`dp[n][m] == A mod 2^64 == A`，一位不差。

**三条缺一不可。** 若转移中出现**除法**或**取 max / 比较大小**，回绕后的值失去大小序，此技巧立即失效。本题恰好是纯加法计数 + 答案有界。

### 返回值

```cpp
return static_cast<int>(dp[n][m]);
```

`unsigned long long` → `int` 是收窄转换，不显式转换会有编译警告。因值确定 `< 2^31`，转换安全。

### 副作用：`continue` 剪枝的语义变了

```cpp
if (dp[i][j] == 0) continue;
```

回绕后，某个真实值巨大的格子有极小概率恰好回绕成 0，于是被跳过。

**不影响正确性**——跳过它等于不加它的值，而它的值就是 0，加 0 和不加一样。

但要记住：**这句现在只是性能优化，不能再当作「此路不通」的判断依据。** 以后若想在这里加别的逻辑（比如统计可达状态数），会出错。

## 空间优化：为什么必须倒序

转移只依赖 `dp[i-1][...]`（推送版则只影响 `dp[i+1][...]`），可压成一维。但 `j` 必须**倒序**：

```cpp
vector<unsigned long long> dp(m + 1, 0);
dp[0] = 1;
for (int i = 1; i <= n; i++) {
    for (int j = m; j >= 1; j--) {          // 倒序！
        if (s[i - 1] == t[j - 1]) dp[j] += dp[j - 1];
    }
}
return static_cast<int>(dp[m]);
```

正序时 `dp[j-1]` 已被本轮更新过，拿到的是 `dp[i][j-1]` 而不是需要的 `dp[i-1][j-1]`。倒序遍历时 `dp[j-1]` 还保留着上一轮的值。

一维版里「不用 `s[i-1]`」的分支变成了**什么都不做**（`dp[j]` 原地保留上一行的值），所以只剩 `if` 里那一句。`dp[0]` 恒为 1，不参与更新。

> 这个「倒序保留上一行」的技巧和 **0-1 背包**完全一致，可对照 `DP-GUIDE.md` 里的背包部分记忆。

本仓库 `solution.cpp` 保留了二维表，便于对照 README 里的手推过程。

## 解法对比

| 解法 | 时间 | 空间 | 能否 AC |
|---|---|---|---|
| 位掩码暴力 | `O(2^m · m)` | `O(m)` | ✗ `m>30` 直接 UB |
| 裸递归 | `O(2^m)` | `O(m)` 栈 | ✗ TLE |
| 记忆化搜索 | `O(n·m)` | `O(n·m)` | ✓ |
| 递推 DP（拉取 / 推送） | `O(n·m)` | `O(n·m)` | ✓ |
| 一维滚动数组 | `O(n·m)` | `O(m)` | ✓ |

无论哪种 `O(n·m)` 写法，**都必须用 `unsigned long long`**，否则会在中间值溢出上翻车。

从暴力到正解的两个跃迁点：

1. **位掩码 → 递归**：从「先全部决策再验证」变成「边决策边匹配」，暴露出 `(i, j)` 这个状态
2. **递归 → 记忆化**：发现 `(i, j)` 相同则结果相同，消除重叠子问题，指数变多项式

## 常见错误

**`dp[i][0]` 初始化为 0。** 整张表归零，答案永远是 0。空串是合法的匹配目标。

**出口顺序反了。** 先判 `i == n` 会让「`i` 和 `j` 同时到头」这个成功情况被误判为失败。

**以为要去重。** 相同字符串的不同下标组合是不同方案，见开头。

**中间值用 `int` 或 `long long`。** 题目只保证最终答案不溢出，中间格子能到 `10^29` 以上，必须用 `unsigned long long` 靠回绕。

**推送版内层写 `j < m`。** `dp[i][m]` 无法向下传递，丢失所有中途配完 `t` 的方案。用 `s="ab"`, `t="a"` 可当场抓出。

**推送版把 `t[j]` 写成 `t[i]`。** `i` 是 `s` 的指针，用它索引 `t` 会比较无关字符，且 `s` 比 `t` 长时越界读。

**一维优化正序遍历。** 读到的是本轮已更新的值，结果偏大。

**位掩码内层逆序。** `for (int i = m-1; i >= 0; i--)` 生成逆序串，破坏子序列的保序性。
