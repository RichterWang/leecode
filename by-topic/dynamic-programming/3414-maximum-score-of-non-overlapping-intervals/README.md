# 3414. 不重叠区间的最大得分

**难度**：Hard　**标签**：动态规划、排序、二分查找、区间调度

## 题目描述

给你一个二维整数数组 `intervals`，其中 `intervals[i] = [l_i, r_i, weight_i]`。区间 `i` 的起点为 `l_i`，终点为 `r_i`，权重为 `weight_i`。

你最多可以选择 **4 个互不重叠** 的区间。所选择区间的 **得分** 定义为这些区间权重的总和。

返回一个至多包含 4 个下标且 **字典序最小** 的数组，表示从 `intervals` 中选中的互不重叠且得分最大的区间。

如果两个区间没有任何重叠点，则称二者 **互不重叠**。特别地，**如果两个区间共享左边界或右边界，也认为二者重叠**。

## 为什么不能贪心

无权版本的"选最多个不重叠区间"可以贪心：按右端点排序，每次选结束最早的。但**一旦带上权值，贪心立刻失效**：

```text
区间 A: [1, 10]，权值 100
区间 B: [1, 2]，权值 1
区间 C: [3, 4]，权值 1
```

贪心按右端点先拿 B、再拿 C，总分 2；实际应该拿 A，得 100。

局部最优（结束最早）不再导向全局最优，必须枚举"选 / 不选"两种决策取最优，也就是 DP。

## 关键一步：按右端点排序

排序是整个解法的地基。按**右端点升序**排好后得到一条性质：

> 若 `arr[j]` 排在 `arr[i]` 前面，则 `arr[j].right <= arr[i].right`

于是"与 `arr[i]` 不冲突的区间"必然构成 `i` 之前的一段**连续前缀**——只要 `arr[j].right < arr[i].left`，那么 `0..j` 整段都不冲突（它们的右端点更小）。

这把"检查是否与已选集合冲突"从集合问题降维成了**一个下标**，才使一维 DP 状态成为可能。

按左端点排不行：右端点会乱序，前缀里可能混着右端点很大、与 `i` 重叠的区间，前缀性质就没了。

## 必须保留原始下标

题目要返回的是**原始下标**，而排序会打乱顺序。因此排序前先把下标打包进去：

```cpp
vector<array<int, 4>> arr(n);   // {left, right, weight, 原始下标}
for (int i = 0; i < n; i++)
    arr[i] = {intervals[i][0], intervals[i][1], intervals[i][2], i};

sort(arr.begin(), arr.end(), [](const array<int,4>& a, const array<int,4>& b){
    return a[1] < b[1];         // 按右端点升序
});
```

之后 `arr[t][3]` 随时能取回原始下标。**不要直接 `sort(intervals)`**，那样下标信息永久丢失。

## 状态定义

```text
dp[r][i] = { 从前 i 个区间中选 r 个不重叠区间的最大权值和,
             取得该分数时字典序最小的原始下标组 }
```

两个维度各自的职责：

| 维度 | 含义 | 为什么需要 |
|---|---|---|
| `r` | 已选了多少个区间 | 题目限制最多 4 个，必须记录配额 |
| `i` | 考察范围是前缀 `0..i-1` | 承接排序带来的前缀性质 |

`i` 采用 1-indexed（`dp[r][i]` 表示前 `i` 个区间），这样 `i = 0` 天然表示空前缀，省掉 `j = -1` 的特判。

代码中用类型别名简化书写：

```cpp
using state = pair<long long, vector<int>>;
vector<vector<state>> dp(5, vector<state>(n + 1, {0LL, {}}));
```

`using` 是 C++11 的类型别名（等价于 `typedef`），**不创建新类型**，纯粹为可读性。`pair` 两个成员的含义：

```text
.first  → long long，最大分数
.second → vector<int>，字典序最小的原始下标组
```

## 转移方程

对第 `i` 个区间做**选 / 不选**的二分决策：

```cpp
int real_idx = i - 1;

// A. 不选：答案与前 i-1 个区间的子问题完全一致
state opt1 = dp[r][i - 1];

// B. 选：拿到权值，配额 -1，可选范围压缩到不冲突的前缀 p
int p = lower_bound(right_end.begin(), right_end.end(), arr[real_idx][0])
        - right_end.begin();

state opt2 = dp[r - 1][p];
opt2.first += arr[real_idx][2];
opt2.second.push_back(arr[real_idx][3]);
sort(opt2.second.begin(), opt2.second.end());
```

注意选的那一支必须是 `dp[r-1][p]` 而**不是** `dp[r][p]`——配额已经消耗一个。写成 `dp[r][p]` 会允许总共选出 5 个区间，突破上限。

## 二分查找 p 的含义

```cpp
vector<int> right_end(n);
for (int i = 0; i < n; i++) right_end[i] = arr[i][1];   // 注意是 arr，不是 intervals

int p = lower_bound(right_end.begin(), right_end.end(), arr[real_idx][0])
        - right_end.begin();
```

`lower_bound` 在有序数组里返回第一个 `>= target` 的迭代器，减去 `begin()` 转成下标。关键在于这个返回值的双重含义：

> 第一个 `>= target` 的下标 **等于** 严格小于 `target` 的元素个数

所以 `p` 的语义是：

```text
p = 有多少个区间的「右端点」严格小于「当前区间的左端点」
```

因为已按右端点排序，这 `p` 个区间恰好就是**前 p 个**，正好对应 dp 第二维的前缀长度，可以直接写 `dp[r-1][p]`，不需要再 `±1`。

### 举例

```text
下标:       0        1        2        3
区间:    [1,2]    [3,5]    [4,7]    [8,9]
right_end:  2        5        7        9
```

处理 `[8,9]` 时 `target = 8`，第一个 `>= 8` 的是 `9`（下标 3），得 `p = 3`。含义是前 3 个区间（右端点 2、5、7）都能与 `[8,9]` 共存，转移用 `dp[r-1][3]`。

### 为什么用 `lower_bound` 而非 `upper_bound`

题目明确规定 **共享端点也算重叠**，所以需要 `end < start`（**严格小于**），这正是 `lower_bound` 对应的语义。若端点相接允许同时选，才该换成 `upper_bound`。

### 易错点：right_end 必须来自 arr

```cpp
right_end[i] = arr[i][1];         // 正确
right_end[i] = intervals[i][1];   // 错误
```

`intervals` 没有被排序（下标打包到 `arr` 后排的是 `arr`），照抄 `intervals` 会得到**乱序**数组，二分查找的前提被破坏，`p` 的值毫无意义，且不再对应 `arr` 的前缀。

反例：

```text
intervals = [[5,6,1], [1,2,1]]

排序后 arr:  [1,2,1,#1]  [5,6,1,#0]
正确 right_end = [2, 6]
错误 right_end = [6, 2]   ← 照抄原顺序
```

处理 `arr[1]`（左端点 5）时：

| | 数组 | 查找 5 | p | 结果 |
|---|---|---|---|---|
| 正确 | `[2, 6]` | 第一个 `>= 5` 是 `6`，下标 1 | `1` | 两个都选，返回 `[0,1]` |
| 错误 | `[6, 2]` | 第一个 `>= 5` 是 `6`，下标 0 | `0` | 只能单选，返回 `[0]` |

`[1,2]` 与 `[5,6]` 显然不重叠，应当都选。这个用例很小，适合手算验证。

## 字典序最小怎么处理

这是本题比普通带权区间调度多出来的难点。

### 思路：让 dp 直接存方案，而不是事后回溯

常规做法是 dp 只存分数、最后倒推路径。但那样在 `dp[r][i] == dp[r][i-1]`（选与不选同分）时必须决定走哪条分支，而**局部选更小的下标不保证整体字典序更小**——选了当前区间会限制后续可选范围，可能导致更靠后的位置反而变大。要正确处理就得在回溯里做多路比较，代码量和出错概率都很高。

由于 **k 最多只有 4**，更省心的办法是：

> 每个状态除了分数，**连带存下取得该分数时字典序最小的那组原始下标**

每个状态多存 ≤ 4 个 `int`，空间开销可忽略。转移时按"先比分数，同分比字典序"取优者，字典序就在 DP 过程中自动维护好了。`k = 4` 这个小上限正是题目给的暗示。

### 三路比较

```cpp
if (opt1.first > opt2.first)      dp[r][i] = opt1;
else if (opt1.first < opt2.first) dp[r][i] = opt2;
else dp[r][i] = opt1.second < opt2.second ? opt1 : opt2;
```

`vector<int>` 的 `operator<` 本身就是字典序比较，直接用即可。

### 下标组必须保持升序

```cpp
opt2.second.push_back(arr[real_idx][3]);
sort(opt2.second.begin(), opt2.second.end());   // 这一步是必需的
```

排序打乱了原始顺序，所以新加入的 `arr[real_idx][3]` **不一定比已有的都大**。例如原始下标 `2` 的区间右端点很小，会排到原始下标 `0` 的前面。

字典序比较的前提是数组本身有序（题目要求返回的也是升序下标数组），所以每次插入后都要重排。长度 ≤ 4，开销可忽略。

也可以改成有序插入，效果相同：

```cpp
auto pos = upper_bound(opt2.second.begin(), opt2.second.end(), arr[real_idx][3]);
opt2.second.insert(pos, arr[real_idx][3]);
```

### 正确性依据

归纳法：每个状态都保存了该子问题下字典序最小的方案。

- 方案 A 继承 `dp[r][i-1]`，它已是那个子问题的字典序最小解
- 方案 B 基于 `dp[r-1][p]` 的字典序最小解，再加一个固定下标

这里有个前提：**加上同一个下标后，原本字典序更小的方案仍然更小**。因为新增元素相同、插入后都保持升序，这个单调性成立，所以在子问题上只保留一个最优解不会丢掉全局最优。

## 返回值

```cpp
return dp[4][n].second;
```

两点说明：

**为什么直接取 `r = 4`。** 本题权值均为正数，`dp[4][n]` 必然不小于 `dp[3][n]`，最大配额的状态就是全局最优。

**长度可能小于 4。** 当选不满 4 个时，`dp[r][i]` 会从 `dp[r][i-1]` 一路继承更少个数的最优解，天然符合"**至多** 4 个"的要求，不需要额外处理。

## 溢出

权值上限 `10^9`，选 4 个可达 `4 × 10^9`，超出 `int` 范围（约 `2.1 × 10^9`）。分数必须用 `long long`，这也是 `state.first` 声明为 `long long` 的原因。

## 边界安全性

`p` 不会造成越界或读到未计算的状态：因为 `arr[real_idx][1] >= arr[real_idx][0]`，第一个 `>= left` 的右端点位置最多就是 `real_idx` 自己，所以 `p <= real_idx < i`，`dp[r-1][p]` 在当前轮次之前已经算好。

## 常见错误

**直接 `sort(intervals)`。** 原始下标永久丢失，无法输出答案。

**`right_end` 填 `intervals` 而非 `arr`。** 数组乱序，二分失效，见上文反例。

**转移用 `dp[r][p]`。** 配额没有消耗，会选出 5 个区间。

**用 `upper_bound`。** 本题共享端点算重叠，必须严格小于，应用 `lower_bound`。

**插入下标后忘记排序。** 字典序比较前提被破坏，同分时可能选出错误方案。

**分数用 `int`。** 4 个权值累加溢出。

**只存分数、事后回溯路径。** 同分时的 tie-breaking 需要多路比较，极易出错。直接在状态里存方案更稳。

## 复杂度分析

设 `n` 为区间数，`K = 4`：

- **时间复杂度**：`O(n log n)` 排序 + `O(K · n · (log n + K log K))` DP ≈ `O(n log n)`
- **空间复杂度**：`O(K · n · K)` = `O(n)`，每个状态存 ≤ 4 个下标

`n` 上限 `5 × 10^4`，完全够用。

## 解法脉络

```text
带权 → 贪心失效 → 上 DP
        ↓
按右端点排序 → "不冲突"可用一个前缀下标表达
        ↓
状态：dp[已选个数][前缀长度]
        ↓
转移：不选 = 缩小前缀；选 = 权值 + 配额-1 的子问题
        ↓
右端点有序 → 二分定位可用前缀，去掉一层 n
        ↓
k 只有 4 → 状态里直接存方案，字典序随 DP 一并维护
```

每一步都在为下一步铺路：排序让状态定义成立，状态定义让转移可写，转移里的 `p` 又反过来依赖排序带来的有序性才能二分。
