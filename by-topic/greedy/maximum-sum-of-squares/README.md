# 最大平方和的好整数

## 题目信息

- **难度**：Medium
- **分类**：Greedy, String, Math
- **相关题目**：LeetCode 类似题（题号待确认）

## 题目描述

给你两个**正整数** `num` 和 `sum`。

如果一个正整数 `n` 满足以下两个条件，则称其为**好整数**：
- `n` 的位数**恰好**为 `num`
- `n` 的各位数字之和**恰好**为 `sum`

一个好整数 `n` 的**分数**定义为 `n` 的各位数字的平方和。

返回一个**字符串**，表示能获得**最大分数**的好整数 `n`。如果有多个可能的整数，返回**最大**的那个。如果不存在这样的整数，返回一个空字符串。

### 示例

**示例 1：**
```
输入：num = 2, sum = 3
输出："30"
解释：
- "30" 的分数 = 3² + 0² = 9
- "21" 的分数 = 2² + 1² = 5
- "12" 的分数 = 1² + 2² = 5
"30" 的分数最大，所以返回 "30"
```

**示例 2：**
```
输入：num = 3, sum = 12
输出："921"
解释：
- "921" 的分数 = 9² + 2² + 1² = 86
这是最大分数，且字典序最大
```

**示例 3：**
```
输入：num = 2, sum = 20
输出：""
解释：两位数最大和为 9 + 9 = 18，无法达到 20
```

## 解题思路

### 核心观察

1. **平方函数的单调性**：较大的数字平方后贡献更大
2. **位权的重要性**：高位的数字决定了整数的大小
3. **贪心最优性**：从高位到低位，每位都填最大可能的数字

### 贪心策略

**从最高位开始，每一位都填尽可能大的数字。**

这样可以同时保证：
1. 整数本身最大（高位大则整体大）
2. 平方和最大（大数字的平方贡献更大）

### 为什么贪心是正确的？

假设存在某个位置填了较小的数 `a`，另一个位置填了较大的数 `b`（其中 `a < b`）。

**平方和比较：**
- 当前方案：`a² + b²`
- 交换方案：`b² + a²`（结果相同）

但是，如果 `a` 在高位，`b` 在低位，交换后整数会变小。因此应该**高位优先填大数字**。

### 具体实现

对于第 `i` 位（从 0 开始，0 是最高位）：

1. **计算剩余信息：**
   - `remain_positions = num - i - 1`：剩余位数
   - `remain_sum`：还需要凑的数字和

2. **计算当前位的取值范围：**
   - **最小值**：`max(0, remain_sum - 9 * remain_positions)`
     - 保证后面的位即使全填 9 也能凑够 `remain_sum`
     - 第一位特殊：至少为 1（不能有前导零）
   
   - **最大值**：`min(9, remain_sum)`
     - 不能超过 9
     - 不能超过剩余和（后面的位可以全填 0）

3. **无解判断：**
   - 如果 `min_digit > max_digit`，说明无法满足条件

4. **贪心选择：**
   - 填入 `max_digit`
   - 更新 `remain_sum -= max_digit`

### 正确性证明

**定理：** 从高位到低位贪心填充最大值，可以得到平方和最大且字典序最大的结果。

**证明：**
1. **平方和最大性：** 由于平方函数的凸性，将较大的数字尽早使用（而不是分散到多个位上）能最大化平方和
2. **字典序最大性：** 高位更大的数字，整体数值更大

## 边界条件

1. **无解情况：**
   - `sum < 1`：至少需要一个非零数字
   - `sum > num * 9`：即使所有位都填 9 也无法达到要求的和

2. **第一位特殊处理：**
   - 最小值至少为 1（避免前导零）

3. **整数溢出：**
   - 使用字符串构造结果，避免整数溢出

## 复杂度分析

**时间复杂度**：`O(num)`  
需要遍历 `num` 位，每位的计算都是 O(1)。

**空间复杂度**：`O(num)`  
结果字符串的长度。
