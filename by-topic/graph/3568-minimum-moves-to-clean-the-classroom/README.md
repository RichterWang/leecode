# 3568. Minimum Moves to Clean the Classroom

## 题目信息

- **难度**：Medium
- **分类**：Graph, BFS, Bitmask, State Compression, Pruning
- **链接**：https://leetcode.com/problems/minimum-moves-to-clean-the-classroom/

## 题目描述

给你一个 `m x n` 的字符网格 `classroom` 和一个整数 `energy`：

- `S` 起点，唯一
- `L` 垃圾，需要全部收集，最多 10 个
- `R` 能量补给站，踏上后能量恢复为 `energy`
- `X` 障碍，不可通行
- `.` 空地

每次可以向上下左右移动一格，消耗 1 点能量。能量为 0 时无法再移动。

返回收集完所有垃圾所需的最少移动次数；无法完成返回 `-1`。

## 解题思路

### 状态设计

裸的 `(x, y)` 不足以描述这道题。真正决定"后续能做什么"的还有两件事：

- **已收集哪些垃圾** —— 决定还差多少才算完成
- **剩余能量** —— 决定还能走几步

这两者都是**路径属性**，不是全局属性。BFS 同一层的不同节点分属不同路径，有的路过 `R` 被补满，有的快耗尽；有的捡了 2 号垃圾，有的没捡。用全局变量记录必然错乱。

所以状态是四元组 `(x, y, mask, energy)`，整个塞进队列里传递。

### 用 bitmask 表示收集进度

先给每个 `L` 编号，存成一张查询表：

```cpp
vector<vector<int>> garbageId(m, vector<int>(n, -1));
if (classroom[i][j] == 'L') garbageId[i][j] = total++;
```

`mask` 的第 k 位为 1 表示 k 号垃圾已收集。`fullMask = (1 << total) - 1` 是低 `total` 位全为 1，即"全部收齐"。

收集时用 `|=`：

```cpp
next_mask |= (1 << garbageId[next_x][next_y]);
```

`|=` 有两个关键性质：**只增不减**（垃圾累积收集，捡过的不会丢）、**幂等**（重复经过同一个 `L` 结果不变）。这正是它优于全局计数器的地方——计数器会被重复递减，越走越少，答案偏小。

题目给出"`L` 最多 10 个"的约束，`2^10 = 1024`，本身就是在暗示状压。

### best 数组：visited 表 + 能量维度压缩

```cpp
vector<vector<vector<int>>> best(m, vector<vector<int>>(n, vector<int>(1 << total, -1)));
```

`best[x][y][mask]` = 曾经以该位置和收集状态到达时的**最大剩余能量**，`-1` 表示未到达过。

它承担两个职责。

**一、它就是这个状态空间的 visited 表，去重键是三元组而非 `(x, y)`。**

普通 BFS 的 `visited[x][y]` 在这道题会剪掉正解——为了绕去 `R` 补能量、或按不同顺序捡垃圾，走回头路是常态。加上 `mask` 维度后，"空手站在 (3,4)" 和"捡了 2 号垃圾站在 (3,4)" 成为两个独立状态，回头路就通了。

同时它也是**终止性的必要条件**，不是可选的加速。有 `R` 的图上，`R → a → b → R → ...` 每次回到 `R` 时能量重置、mask 不变，状态完全重复，队列永远不空。`energy` 单调递减本是天然的终止保证，但 `R` 把它破坏了。

**二、存 int 而非 bool，把 energy 维度压缩掉。**

严格来说去重表该是四维 `visited[x][y][mask][energy]`，规模 20×20×1024×51 ≈ 2100 万，内存吃紧。

省掉这一维靠的是**能量的单调有益性**：同一个 `(x, y, mask)`，能量多的一方能做的事是能量少那方的超集，严格不劣。所以"到过哪些能量值"这个集合不需要完整保存，只记上界即可：

```
四维 bool 表：记录该状态到过 {3, 7, 12} 这些能量
三维 int  表：只记 12
```

能量 3 和 7 能到的地方，能量 12 全都能到。这是**无损压缩**——两者剪掉的状态完全相同，但内存降到 41 万个 int。

这也是为什么必须存 int：如果新状态能量**更多**（哪怕步数更多），就必须放行，因为多出的能量可能让它走到之前到不了的地方。布尔表会把这种"步数换能量"的状态误剪。

### 转移的三个细节

```cpp
int next_energy = temp[3] - 1;                    // 先付移动代价
if (... == 'L') next_mask |= (1 << garbageId[...]);
if (... == 'R') next_energy = energy;             // 落地后再补满
```

**扣减与补满的顺序不能对调**，否则等于免费移动。

**`R` 无条件补满**。题目说"可以"恢复，是可选的；但能量单调有益，不补满的状态一定被补满的状态支配，`best` 会自动剪掉，不用纠结。

**剪枝用 `>=` 而非 `>`**：

```cpp
if (best[next_x][next_y][next_mask] >= next_energy) continue;
```

能量相等时，新状态与旧状态能力完全相同，但步数只会更多（BFS 层序保证），毫无优势。用 `>` 会让大量等价状态涌进队列，实测超时。

### 为什么返回的 step 一定是最优解

分两步。

**层序性质。** 每次移动的代价恒为 1——踏上 `R` 补能量、踏上 `L` 收垃圾都不额外消耗步数。所以"步数"与"BFS 层数"严格对应，队列中的状态按步数非递减排列。首次 pop 到 `mask == fullMask` 时，`step` 就是所有可行解里最小的。（也正因边权全为 1 才能用 BFS；若代价不等就得换 Dijkstra。）

**剪枝不丢最优解。** 设被丢弃的新状态 `B = (x, y, mask, e_B)` 在第 `k_B` 层，表里已有记录来自 `A = (x, y, mask, e_A)` 在第 `k_A` 层。由剪枝条件得 `e_A >= e_B`；由 `best` 按 BFS 顺序写入得 `k_A <= k_B`。A 在两个维度上同时不劣于 B。

把 B 后续任意一条完成任务的动作序列 `σ` 接在 A 后面：**走得通**（`σ` 每步耗 1 点能量，A 起手能量不少于 B，中途遇 `R` 两边补到同值，差距只缩不扩）；**不会更慢**（总步数 `k_A + |σ| <= k_B + |σ|`）。所以 B 能达成的结果 A 都能达成且不更差，丢掉 B 无损。这就是**支配关系**。

反向不成立：新状态能量更多时两者互不支配，代码正确地放行并更新 `best`。

### 两个边界情形

**能量耗尽被 `continue`** 不是剪枝而是死路：能量为 0 无法移动，接不出任何后续。此时所在格必然不是 `R`（踏上 `R` 的瞬间已补满），也无"原地充电"可能。若它恰好 `mask == fullMask`，上一行判断已经 return，不会被吃掉。

**目标状态被剪掉**：对应记录的状态 `A` 有相同的 `fullMask` 且层号不更大，它会在自己那一层 return，步数不会更差。

### 复杂度

**时间复杂度**：`O(m × n × 2^L × 4)`。状态数 20 × 20 × 1024 ≈ 41 万，每个状态 4 个转移，加上支配剪枝带来的有限重访。

**空间复杂度**：`O(m × n × 2^L)`，约 41 万个 int。

## 常见错误

`wrong_solution.cpp` 保留了第一次尝试的版本，思路是"普通网格 BFS + 全局计数器"，用作反面教材。

设计层面的根本性错误：

1. **状态维度缺失** —— 只有 `(x, y)`，丢了 mask 和能量
2. **`temp_energy` 是全局变量** —— 但能量路径相关，同层不同节点走的路不同
3. **`need_collect` 全局递减** —— A 路径捡的垃圾算到 B 头上；同一个 `L` 被反复减，提前归零
4. **`visited[x][y]` 封死回头路** —— 绕去 `R` 补能量、换顺序捡垃圾都被剪掉

实现层面的低级 bug：

5. **`m` / `n` 含义搞反** —— `classroom` 是 `vector<string>`，`.size()` 是行数，`[0].size()` 是列数；写反后又拿 `m` 当行数遍历，非方阵直接越界
6. **邻居扩展全写成自己** —— 障碍检查、`visited` 标记、入队三处都用了 `temp` 而非 `next`，push 自己导致队列无限自我复制
7. **终止判断用 `energy` 而非 `temp_energy`** —— `energy` 是最大容量全程不变，该分支永不触发

调试过程中还遇到一个典型手滑：

```cpp
if (total = 0) return 0;   // = 是赋值，应为 ==
```

它把 `total` 清成 0，导致 `best` 第三维只开 1 格；而 `garbageId` 在此之前已填好，编号照旧是 0、1、2……于是 `next_mask` 一旦非 0 就越界。加 `-Wall` 可当场抓住这类错误。
