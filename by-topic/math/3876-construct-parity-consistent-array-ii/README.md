# 3876. Construct Parity Consistent Array II

**难度**: Medium
**标签**: Array, Math, Sorting, Parity（奇偶性）

---

## 题目描述

给你一个长度为 `n` 的数组 `nums1`，其中包含 **互不相同** 的整数。

你需要构造另一个长度为 `n` 的数组 `nums2`，使得 `nums2` 中的元素要么全部为 **奇数**，要么全部为 **偶数**。

对于每个下标 `i`，你必须从以下两种选择中 **任选其一**（顺序不限）：

- `nums2[i] = nums1[i]`
- `nums2[i] = nums1[i] - nums1[j]`，其中 `j != i`，且满足 `nums1[i] - nums1[j] >= 1`

如果能够构造出满足条件的数组，则返回 `true`；否则，返回 `false`。

---

## 解题思路

题目看起来是构造题，实际上只需要判断可行性，而且判据非常简洁。核心是想清楚**每个元素能达到哪些奇偶性**。

### 第一步：减法对奇偶性的影响

只关心奇偶，那么 `nums1[i] - nums1[j]` 的奇偶性完全由两者的奇偶性决定：

| `nums1[i]` | `nums1[j]` | 差的奇偶性 |
|---|---|---|
| 偶 | 偶 | 偶（不变）|
| 偶 | 奇 | 奇（翻转）|
| 奇 | 奇 | 偶（翻转）|
| 奇 | 偶 | 奇（不变）|

结论：**减去一个奇数会翻转奇偶性，减去一个偶数不会改变奇偶性。**

所以对下标 `i` 来说：
- 保持原奇偶性总是可以做到（直接选 `nums2[i] = nums1[i]`）
- 想翻转奇偶性，必须找到一个奇偶性与 `nums1[i]` 相反的 `nums1[j]`，且要满足 `nums1[i] - nums1[j] >= 1`，也就是 `nums1[j] < nums1[i]`

### 第二步：`>= 1` 这个约束意味着什么

`nums1[i] - nums1[j] >= 1` 等价于 `nums1[j] < nums1[i]`（元素互不相同，不会出现相等）。

也就是说，**一个元素只能减去比它更小的元素**。排序后就很直观：下标 `i` 只能从它左边挑一个减数。

这直接推出一个重要结论：排序后的**最小元素无法翻转奇偶性**，因为它左边没有任何元素可选，它只能保持自己原本的奇偶性。

所以最小元素的奇偶性就锁定了整个 `nums2` 的目标奇偶性。

### 第三步：分两种情况

设排序后数组为 `a[0] < a[1] < ... < a[n-1]`。

**情况 A：`a[0]` 是奇数 → 一定可以，返回 `true`。**

目标定为「全奇数」。对每个 `i >= 1`：
- 若 `a[i]` 本身是奇数，直接保留
- 若 `a[i]` 是偶数，就减去 `a[0]`。`a[0]` 是奇数所以奇偶性翻转成奇数，且 `a[0] < a[i]` 保证了差 `>= 1`

`a[0]` 自己保留即可。每个位置都能凑成奇数，构造成功。

**情况 B：`a[0]` 是偶数 → 目标只能是「全偶数」。**

`a[0]` 无法翻转，只能是偶数，所以整个数组的目标就是全偶数。此时对每个奇数元素 `a[i]`，需要减去某个奇数 `a[j]`（`j < i`）来翻转成偶数。但只要存在奇数，最小的那个奇数左边全是偶数，没有奇数可用，它就无法变成偶数。

所以只要数组中存在任何奇数，就返回 `false`；全是偶数则返回 `true`。

### 判据总结

```text
排序后：
  a[0] 是奇数           -> true
  a[0] 是偶数且全为偶数  -> true
  a[0] 是偶数且含奇数    -> false
```

也就是说，本质判据是：**最小元素是奇数，或者整个数组都是偶数。**

## 代码逻辑对照

```cpp
sort(nums1.begin(), nums1.end());

// 最小是偶数、最大是奇数 -> 一定存在奇数 -> false（快速剪枝）
if(nums1[0] % 2 == 0 && nums1[n - 1] % 2 == 1) return false;

// 最小是奇数 -> 全部可以变成奇数
if(nums1[0] % 2 == 1) return true;

// 剩下：首尾都是偶数，检查中间是否夹着奇数
for(int i = 1; i < n - 1; i++)
{
    if(nums1[i] % 2 == 1) return false;
}
return true;
```

三个分支正好覆盖了上面的三种情况：

- 第一个 `if` 是情况 B 的快速剪枝：首偶尾奇说明必有奇数
- 第二个 `if` 是情况 A
- 循环处理情况 B 的剩余部分：首尾都是偶数时，中间还可能藏着奇数

循环写成 `i < n - 1` 是安全的，因为进到循环时已经确认了 `a[0]` 和 `a[n-1]` 都是偶数，无需重复检查。

---

## 关键点与易错处

**只有最小元素受限。** 容易漏掉的推理是「谁不能翻转」。非最小元素总有更小的元素可减，唯独最小元素没有退路，它决定了全局目标奇偶性。

**`>= 1` 不是 `> 0` 的花式写法。** 在整数域上两者等价，但它明确排除了 `nums1[i] - nums1[j] = 0`，也就是不能减去等值元素。题目已保证互不相同，所以这个约束实际上只是「减数必须更小」。

**负数取模。** 如果题目允许负数，`nums1[0] % 2 == 1` 对负奇数会得到 `-1` 而不是 `1`，判断会失效。稳妥写法是 `abs(nums1[0]) % 2 == 1` 或 `(nums1[0] & 1) != 0`。当前实现假设元素为正整数。

**排序修改了入参。** `sort` 直接改动了传入的 `nums1`。判定型题目不影响正确性，但如果调用方后续还要用原顺序，需要先拷贝一份。

**不需要真的构造出 nums2。** 题目只问可行性，找到判据后 `O(n)` 一次扫描即可。想着去模拟构造过程反而容易写复杂。

---

## 复杂度分析

- **时间复杂度**: `O(n log n)`，排序占主导；判定部分是 `O(n)`
- **空间复杂度**: `O(1)` 额外空间（原地排序，不计排序自身的递归栈）

> 顺带一提：这题其实不需要排序。只要求出最小值，再统计是否存在奇数，就能在 `O(n)` 时间内给出答案。排序让分支推理更直观，代价是多了一个 `log n`。
