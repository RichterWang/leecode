# 3348. Smallest Divisible Digit Product II

## 题目信息

- **难度**：Hard
- **分类**：Math, Greedy, Number Theory, Digit DP
- **链接**：https://leetcode.com/problems/smallest-divisible-digit-product-ii/

## 题目描述

给你一个字符串 `num` 表示一个正整数，以及一个整数 `t`。

如果一个整数**没有任何数位是 `0`**，我们称这个整数是**无零数字**。

请返回一个字符串，表示大于等于 `num` 的**最小无零整数**，且其**各数位之积能被 `t` 整除**。

如果不存在这样的数字，返回 `"-1"`。

## 解题思路

### 方法一：暴力枚举（存在性能问题）

从 `num` 对应的整数开始，逐个向上枚举候选数字：

1. 使用 `stoll(num)` 将字符串转为整数作为起点
2. 从起点开始遍历，检查每个候选数字
3. 对每个候选数字调用 `isValid` 判断是否满足条件：
   - 数位中不能有 `0`
   - 各数位乘积能被 `t` 整除
4. 第一个满足条件的数字就是答案

#### 性能瓶颈

当 `num` 很大时，候选范围可能非常广，枚举到 `1e15` 会超时。

例如：
- `num = "1234"`, `t = 256`
- 如果从 `1234` 开始暴力枚举，可能需要检查大量候选数字

这种解法只能通过小数据测试用例。

#### 为什么会超时

- 搜索上界设为 `1e15`，即 `1,000,000,000,000,000`
- 逐个检查每个数字的数位乘积
- 在大数据范围下时间复杂度无法承受

### 方法二：贪心构造 + gcd 追踪剩余因子

这是可以通过的解法。

#### 1. 先判断是否有解

数位只能是 `1..9`，它们的质因子只有 `2, 3, 5, 7`。

所以先把 `t` 中的 `2, 3, 5, 7` 除尽：

- 如果还有剩余，说明 `t` 包含 `11` 或更大的质因子，直接返回 `"-1"`

#### 2. 把 `t` 分解成最少个数位

`factorize()` 从 `9` 往 `2` 贪心除，优先用大数位。

这样得到的数位个数最少，因为一个 `9` 能顶两个 `3`，一个 `8` 能顶三个 `2`。

#### 3. 位数不能变短

这是最容易错的地方。

即使所需数位很少，结果也必须 `>= num`，所以不能直接返回一个位数更少的数。

- 只有当所需数位个数 `k > n` 时，才会真的变长
- 否则必须保持 `n` 位，不够的位用 `1` 填充

用 `1` 填充是安全的，因为 `1` 不影响数位之积。

#### 4. 用 gcd 追踪剩余需求

定义 `prefixRem[i]`：保留 `num[0..i-1]` 这些数位后，`t` 还有多少没被约掉。

递推式是：

```cpp
prefixRem[j + 1] = prefixRem[j] / gcd(prefixRem[j], num[j] - '0');
```

这比“提前算出一个固定数位组合”更灵活，因为前缀已经贡献的因子会被自动扣除。

如果 `prefixRem[n] == 1` 且 `num` 本身无零，说明 `num` 自己就是答案。

#### 5. 枚举分岔位

从右往左枚举分岔位 `i`：

- `num[0..i-1]` 保持不变
- 第 `i` 位放一个比 `num[i]` 更大的数字
- 后面 `cnt = n - 1 - i` 位可以自由填

对每个候选数字 `d`，算出剩余需求 `rem2`，再分解成 `tail`：

- 如果 `tail.size() <= cnt`，说明后面的位够用，可行
- 不够的位用 `1` 补在前面，`tail` 升序放在后面

**为什么从右往左枚举**：`i` 越靠右，保留的 `num` 前缀越长，结果越小。所以第一个可行解就是最优解。

#### 6. 兼底：位数加一

如果 `n` 位怎么都构造不出来，就用 `n + 1` 位：

- 前面补 `n + 1 - k` 个 `1`
- 后面接上 `base` 升序数位

### 为什么 `1` 可以随意填充

`1` 乘到乘积里不会改变结果，而且 `1` 是非零数位里最小的，放在高位能使整体数字最小。

### 复杂度

#### 方法一（暴力）

**时间复杂度**：`O(k)`，其中 `k` 是实际检查的候选数字个数。在最坏情况下 `k` 接近 `1e15`，无法通过。

**空间复杂度**：`O(1)`。

#### 方法二（贪心构造）

设 `n` 为 `num` 的长度。

**时间复杂度**：`O(n * 9 * log t)`，枚举分岔位和候选数字，每次做一次分解。

**空间复杂度**：`O(n)`，用于 `prefixRem` 和结果字符串。
