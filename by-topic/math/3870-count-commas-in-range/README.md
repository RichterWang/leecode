# 3870. 统计范围内的逗号

**难度**：Easy  
**标签**：数学、计数

## 题目描述

给你一个整数 `n`。

返回将 `[1, n]`（包含两端）范围内的所有整数以标准数字格式书写时，所使用的逗号总数。

在标准格式中，从右边开始，每三位数字后插入一个逗号：

```text
999          → 999
1,000        → 1 个逗号
999,999      → 1 个逗号
1,000,000    → 2 个逗号
```

位数少于四位的数字不包含逗号。

## 当前错误解法

当前代码尝试不断将 `n` 除以 `1000`，并使用 `offset` 计算不同位数区间产生的逗号数：

```cpp
while (n / 1000 != 0) {
    int temp = n - 1000 + 1;
    ans += temp * offset;
    offset = offset << 3;
    n = n / 1000;
}
```

这个思路在 `n < 1,000,000` 时可能得到正确结果，但进入第二个逗号层级后就会出错。

## 问题分析

### 1. 左移三位等于乘以 8

代码：

```cpp
offset = offset << 3;
```

等价于：

```cpp
offset *= 8;
```

位移操作处理的是二进制位。左移一位乘以 `2`，左移三位乘以：

```text
2³ = 8
```

这和十进制中每三位增加一个逗号没有直接关系。

“每三位数字”不代表应该把权重左移三位，也不代表应该乘以 `1000`。每个达到新阈值的数字只会比之前多贡献一个逗号。

### 2. 修改 `n` 后丢失原始上界

执行：

```cpp
n /= 1000;
```

后，下一轮中的 `n` 已经不再是题目给定的原始上界，因此：

```cpp
n - 1000 + 1
```

无法表示下一层逗号的真实贡献。

统计每一层时，都应该使用原始的 `n`。

### 3. 第二层逗号不需要乘权重

以：

```text
n = 1,000,000
```

为例。

所有 `[1,000, 1,000,000]` 中的数字都至少有第一个逗号，贡献：

```text
1,000,000 - 1,000 + 1 = 999,001
```

只有 `1,000,000` 达到了第二个逗号的阈值，额外贡献：

```text
1,000,000 - 1,000,000 + 1 = 1
```

因此正确答案是：

```text
999,001 + 1 = 999,002
```

当前代码却会计算为：

```text
999,001 × 1 + 1 × 8 = 999,009
```

所以错误从第二个逗号层级开始出现。

## 正确思路：按逗号阈值分别统计贡献

每一个逗号位置都有对应的最小数字：

| 逗号层级 | 起始数字 | 该层贡献 |
|---|---:|---:|
| 第一个逗号 | `1,000` | `n - 1,000 + 1` |
| 第二个逗号 | `1,000,000` | `n - 1,000,000 + 1` |
| 第三个逗号 | `1,000,000,000` | `n - 1,000,000,000 + 1` |

只有当 `n` 不小于相应阈值时，该层才有贡献。

因此总数可以写成：

```text
max(0, n - 1,000 + 1)
+ max(0, n - 1,000,000 + 1)
+ max(0, n - 1,000,000,000 + 1)
+ ...
```

### 为什么需要逐层累加

对于：

```text
1,000,000
```

它具有两个逗号，因此会被统计两次：

1. 它不小于 `1,000`，对第一个逗号贡献一次；
2. 它不小于 `1,000,000`，对第二个逗号再贡献一次。

这种按阈值累计的方法会自然得到每个数字实际包含的逗号数量。

## 正确代码

```cpp
class Solution {
public:
    int countCommas(int n) {
        long long answer = 0;

        for (long long threshold = 1000;
             threshold <= n;
             threshold *= 1000) {
            answer += static_cast<long long>(n) - threshold + 1;
        }

        return static_cast<int>(answer);
    }
};
```

## 使用 `long long` 的原因

如果 `threshold` 使用 `int`，当它达到：

```text
1,000,000,000
```

后再执行：

```cpp
threshold *= 1000;
```

会超出 `int` 的表示范围并产生有符号整数溢出。

使用 `long long` 可以安全保存下一次计算得到的阈值。

累计答案也使用 `long long`，可以避免中间计算溢出。最终返回类型按照题目函数签名转换为 `int`。

## 示例分析

### 示例 1

```text
n = 999
```

没有数字达到 `1,000`：

```text
答案 = 0
```

### 示例 2

```text
n = 1,234
```

只有 `[1,000, 1,234]` 中的数字包含逗号：

```text
1,234 - 1,000 + 1 = 235
```

答案为：

```text
235
```

### 示例 3

```text
n = 1,000,000
```

第一个逗号的贡献：

```text
1,000,000 - 1,000 + 1 = 999,001
```

第二个逗号的贡献：

```text
1,000,000 - 1,000,000 + 1 = 1
```

总计：

```text
999,002
```
